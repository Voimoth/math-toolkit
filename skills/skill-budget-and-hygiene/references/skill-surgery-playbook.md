# 技能外科手术：改名 / 拆分 / 压缩

三类改动的逐步操作与验收。规则本身（预算、分层、去重）在 SKILL.md，这里只写「怎么做、怎么证明做对了、怎么回退」。

## 一、改名（技能换一个名字）

改名不是 `mv` 一个目录就完事——技能名同时活在七处，漏一处就会出现「按新名字找不到、按旧名字加载失败」的幽灵引用。

1. 先量引用面：`grep -rln '<旧名>' ~/.hermes/skills ~/.hermes/memories ~/.hermes/SOUL.md`。只看命中文件数就知道代价，几处引用的小技能可以放心改。
2. `mv ~/.hermes/skills/<分类>/<旧名> ~/.hermes/skills/<分类>/<新名>`。
3. 改 frontmatter：`name`、`description`（≤60 字符、**不留空格**）、`tags`、顺带加 `reviewed: <今天>`。
4. 改正文标题与「## 相关」里指向自己的旧名。
5. 全局替换其它文件里的引用（`grep -rl` 出的清单，逐个 sed/patch）。
6. 内存：`memories/MEMORY.md` 里按技能名写的指引要一起改。
7. 机读缓存两处（不改就会让 curator 误判「新技能零使用」）：
   - `skills/.usage.json`：把旧名键改名为新名（保留 created_at / use 计数），否则新技能计数归零、14 天后被判 stale。
   - `.skills_prompt_snapshot.json` 里该条目的 `skill_name` / `frontmatter_name` / `rel` / `description`。
8. 发布器（若该技能已进同步仓库）：`sync/sync.sh` 的技能清单、`sync/local/exclude.txt` 的排除路径、README 表格；旧目录要 `git rm -r` 掉，否则仓库里两份并存。改完跑一次 `bash sync/sync.sh`。
9. 验收：`grep -rn '<旧名>' ~/.hermes/skills ~/.hermes/memories` 必须为 0（`.curator_ledger.jsonl` 这类历史账本除外）；`hermes skills list | grep <新名>` 有行；`skill_view(<新名>)` 能返回内容且 `linked_files` 正常。

判别规则：**内容层按课程命名，不按数学分支命名**。课程主题漂移时改内部小节，不改名；名字与内容不符本身就是一种过时（索引里会显示成一句误导性的话）。

## 二、拆分（把超大 `##` 节搬进 references）

用 `scripts/split-skill.py`，不要手搬：

```
python3 scripts/split-skill.py <SKILL.md 路径> --dry            # 先看节表
python3 scripts/split-skill.py <path> --move '节标题前缀=references/<文件名>.md' ...
```

- 多个 `--move` 指向同一文件会合并进那个文件。
- 搬走的节在正文留：节标题 + 该节第一段（截断 260 字符）+ `→ 全文见 references/…`。选节时优先搬「带日期的实战记录、案例叙述、长清单、环境快照」；「每轮都要用的判据」留在正文。
- **目标文件名避开已有文件**：同主题已有 references 时先 `ls references/`，否则覆盖掉别人的内容（本项目就有一批同名 reference）。

### 编号列表的坑（脚本化必看）

技能正文里常有多组各自从 1 开始编号的列表（顶层判据 1–25 与子节里的 1–9 混在同一个文件中）。两种失败的写法：

- 按空行切块：原文编号项之间不一定有空行，**整段被判成一个 block**，只认出少数几条。
- 以编号为 dict 键：第二组 `1.` 覆盖第一组，正文留下的是错条目（出现「第 7 条讲的是别人的内容」这种串号）。

正确做法：逐行扫描，只接受**编号严格递增**的序列（`n == last + 1` 才收），其余编号视为子列表忽略；条目续行按缩进（行首空格）判定，遇到非缩进行结束该条。抽完必须打印条数与首尾两条核对。

### 验收三件套

1. **子串证全**：每个搬走的节，原文 `in` references 文件且 `not in` 新正文（脚本已内含；手改时自己断言）。
2. **YAML 还能解析**：`yaml.safe_load(frontmatter)` 且 `name`/`description` 都在（改过标题或 frontmatter 时尤其要跑）。
3. **dangling 只算本目录**：正文里 `references/x.md` 在本技能目录找不到才算问题；形如「见 <技能B> 的 references/<文件>」的跨技能指针是正常的，**不要为了消警告复制文件过来**。

## 三、压缩成骨架（有损，最易丢判据）

适用：某节本身就是「每轮要用的判据」不能整节搬走，但太长。

- 保留形态：每条编号 + 判据首句（≤120–150 字符），案例、原话、反例全部进 references。
- **原文整节必须先原样存进 references**，再重建正文骨架——先压后存等于丢掉被截断的那部分。
- 压完核对：条数与原文件一致、抽检首条/中段/末条的内容确实属于该编号（防串号）。
- 正文里被压掉的具体数字/边界，在骨架行尾写一句「细节读 `references/<文件>`」；否则未来只读正文会以为自己掌握全部判据。

## 四、`check-skill-facts.py` 的误报三类

跑到几十条时先分类，不要逐条改：

1. **示例型路径**（`~/Desktop`、`~/.config/<某应用>`、`~/myapp`）——脚本已用前缀白名单过滤，不要加回。
2. **历史记录**（「当时输出到 X」「原目录保留」）——加一句「X 已于 <年月> 清理/拆分为 …」即可，不要改写成现在的路径（会造假事实）。
3. **运行时产物**（`*.log`、`*.db`、`*.pid`、探针文件、临时 html）——按后缀跳过，这类本来就只有跑过才有。

剩下的才是真失效，按「换新路径」或「删整句」二选一处理；同一批里做完再跑一遍，数字应显著下降（本次 282 → 20）。

## 五、回退

- 拆分与改名都是**可逆**的：拆分的内容零删改躺在 references（可原样拼回），改名把目录名与 frontmatter 改回即可。
- 「压缩成骨架」本身不可逆，但原文在 references 里，同样可拼回。
- 备份（`cp` 或 `tar` 到 scratch）在验收通过后删掉——保留的依据是 references 里有原文，不是备份文件。
- 已发布到同步仓库的技能，回退点是改动前那次 commit；报改动时把 commit 号一起给他。
