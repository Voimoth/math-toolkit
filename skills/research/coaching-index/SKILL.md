# 学科辅导总索引(各科讲到哪 → 去哪个技能)

**用途**:任意新会话开始辅导前先看这里。用户 2026-10-03 提出「把各个学科你给我讲过了什么、有哪些要点记录在一个专门的 skill 中,这样就不会换一个对话就从 0 开始」——本技能就是那个入口:给全科一张表(讲到哪、要点沉在哪)。
**具体内容不复制进本文件**,仍在各课程技能里,避免两处不一致。

## When to Use

- 新会话要开始某科辅导/复习 → 先读「全科一览」定位对应课程技能。
- 用户问「某科我们讲到哪了 / 之前讲过什么」。
- 要决定是否给某科新建内容层技能。

## 三层分工(已定型,勿改)

1. **方法层**:`math-coach` —— 怎么教(模式 A 因果链 / 模式 B 陪练状态机 / 用户校准条目)。**只此一处**;
   课程技能里不再重复方法(2026-10-02 曾在两个技能里各抄一份要求,被用户当场指正)。
2. **内容层**:每门课一个技能 —— 老师记号、讲义来源、进度、已沉淀卡点、教学边界。
3. **本索引**:全科一览 + 进度 + 待建清单。

## 用户当前工作方式(2026-10-03 定型,新对话直接沿用)

- **整理用户手写笔记的标准流水线**:pdftoppm 300dpi 转图(中间产物放 `~/.hermes/cache/`,**不进 vault**) → 视觉模型逐页转写(脚本见 `math-notes-transcription`) → 机械修复(去前言/水印/坏定界符) → 按内容切成章节 → **派子代理并行规范化(整门课约 10 个;每个只读同一份统一规范文件)** → 父代理统一复核(断链/emoji/渲染宏/禁用词/抽查/**交换图渲染与箭头方向**) → 建 `00-总览` 与 `_索引` → git 提交。**校对照原图逐页回图**,分多轮(用户会发现第一轮漏掉的错别字)。完整流程与踩坑见 `math-notes-transcription` 的 `references/whole-course-batch-workflow.md`。
- **交付前自检清单**(每轮都要跑):断链(对全库 basename 比对)、emoji、`\( \) \[ \]` 坏定界符与 `$` 配对、**MathJax 不支持的宏**(`\sh`/`\cancel`/`\textsuperscript`)、禁用词(作业/题号/出处)、`\sharp`(应为 `\#`)。
- 用户会**逐条回复存疑点**并要求落实;他不喜欢笔记里出现整理者的疑问框(存疑只用行内 `[?]`,分析写进交付报告)。

## 维护规则

- **本技能的本职是「各科讲过了什么」的账本,不只是索引**(用户 2026-10-03 特别强调:换对话不许从 0 开始)。旧进度/复盘结论没落盘 = 漏做, 当轮补。
- **讲透一段 → 当轮更新**:先写进对应课程技能(进度 + 卡点 + 要点),再改本表那一行(用户明令「一边做一边整理,不要攒到最后」)。
- 本表**只放一行摘要**,不复制内容。
- 新建/删除课程技能时同步改本表;vault 新增科目时先在 `_索引.md` 登记(vault README 的规矩),再在此加行。
- 判断「某科该不该立内容库」:已有稳定的老师记号 + 已沉淀卡点 + 会长期复习 → 立;否则先只留在 vault 与 `math-coach` 的一般记录里。
