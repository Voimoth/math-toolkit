# 用户数学资料库整理(/mnt/e/书籍)

管理用户(中科大中法班数学系大二)的本地数学资料库 `/mnt/e/书籍/`。目标:保持分类体系稳定,新增资料必须**并入既有结构**。

## 触发条件

- 用户要求整理/归档书籍、PDF、讲义
- 新增外部分享包(如 pika)需要并入资料库
- 用户问"XX 资料应该放在哪"
- 用户提到"分类""整理""并入""重复""查重"等词

- 用户问纸质书/实体书怎么转电子档、要不要买扫描仪（走 `references/paper-to-digital.md`）

## 铁律(用户明确纠正过,务必遵守)

> **用户原话:"整合进我原有的分类体系,而不是直接新建文件夹"**

1. **禁止新建顶层文件夹**(/mnt/e/书籍 下只应有:分析、代数、数学专业书籍、数学学习方法、物理)。
2. **分类逻辑**:
   - 与**当前课程强相关** → `/mnt/e/书籍/分析/` 或 `/mnt/e/书籍/代数/`(课程讲义按 分析I/II/III、代数I/II 分子目录)
   - **其余所有材料** → `/mnt/e/书籍/数学专业书籍/` 下按学科子目录
   - **数学学习方法类**(学习方法/自学指南/解题技巧/思维洞察/数学家访谈)→ `/mnt/e/书籍/数学学习方法/`
3. **移动而非复制**(省空间);完成后删除临时容器文件夹。
4. 大规模移动前先向用户确认关键决策点;用户信任时可按映射表直接执行并给完整报告。
5. 用户明确说"删掉就好"(如近世代数 5 本书与体系不相容)时,可直接删除该文件夹。
6. **顶层目录同时就是检索权重,别随手挪。** `bookdex` 按根目录定层级:只有 `分析/代数/物理/数学学习方法`
   四个顶层算 tier 3(课程在用),`数学专业书籍` 是 tier 1;路径里带 `MPSI` 的提到 tier 2。
   所以把课程书挪进 `数学专业书籍/` 等于给它降权,反过来乱加顶层文件夹会让噪声书浮上来。
   挪完跑一次 bookdex 增量索引,并用 `select tier,count(*) from books group by tier` 核一下分布。

## 整理工作流

1. **先看结构**:列出 /mnt/e/书籍 顶层 + 目标学科目录现状,确认既有分类
2. **制定映射表**:新资料每个子目录 → 对应学科目录(参考 references/library-mapping.md)
3. **关键决策点先确认**(若拿不准):并入既有目录 vs 新建子目录、课程相关判定、散乱文件归属
4. **执行**:`mv -n`(先确认目标不存在);跨盘移动会先复制再删源,大文件先 `du` 核对大小再删源
5. **验证 + 报告**:文件数、大小、最终结构
6. **归档完把目录索引补上**:`~/.local/share/bookdex/venv/bin/python ~/.local/share/bookdex/index.py`(增量,只处理新增/改动文件)。
   `bookdex` 是全库「书名 + 书签目录」索引,不跑它,刚归进来的新书在「哪本书讲过 X」的查询里是**隐形**的——
   会给用户「书库里没这个」这种反向错误结论。同理,大删/改名之后也要跑一次让存量同步。
   - **法文资料归档后核一眼 OCR 语种**：bookdex 扫描件按语种选 tesseract 语言包（法文走 `fra+eng`），
     判错的记录 `dir_src` 会是 `ocr:eng`；要重刷必须先 `update books set dir_src='' where path like …`
     再跑增量——增量只处理 `dir_src=''` 的书，直接重跑不会动它。刷完抽查带重音的法文词
     （théorème / Algèbre / polynôme）能命中才算对。
   - **改 bookdex 的 index.py/query.py 前先确认没有后台增量在跑**：长跑会被切成后台进程并持有旧版模块，
     跑完会把旧逻辑的结果写回去（语种标签、dir_text 都可能被覆盖，而且从标签上不易察觉）。
     改前 `ps aux | grep '[i]ndex.py'`，改后核一遍 `select dir_src,count(*) from books group by dir_src`，
     并逐条对一下 `ocr:*` 标签是否与当前 `ocr_lang(path)` 一致。

## 查重工作流(重复文件清理)

用户会要求清理重复书籍。**精确查重必须用哈希,不能用文件名/大小判断**:

1. **先按文件大小分组**(`Group-Object Length`),只对同大小的组算哈希——大库(1万+文件)直接全量哈希太慢
2. **哈希用系统 `md5sum`(秒级完成万级文件)**;需要结构化报告时用 Node 脚本(`scripts/find_duplicates.js`,本机 node 在 `~/.hermes/tools/`)。脚本见 `scripts/find_duplicates.js`(只读,生成报告)和 `scripts/gen_delete_list.js`(生成"保留/删除"清单,不实际删除)
3. **同名文件组**≈重复(验证 MD5 一致后确认);同大小但不同名的也需要 MD5
4. **保留策略**:每组按路径排序保留第一个(通常是主分类目录),删除副本
5. **删除前必须向用户确认**:列出删除文件数+总大小+典型示例,并指出特殊类型(如"长期更新.几千T资源大合集"这类出现在 14 个目录的资源索引 .doc——问用户是否全删)。不可直接批量删除大量文件
6. **执行删除**用 `scripts/delete_duplicates.js`(读清单 → 删"删除:"行 → 保护名单防误删临时文件 → 记日志)。2026-08 实测:13,762 文件扫出 3,485 个重复,删除 0 失败,释放 ~55GB
7. 完成后删除临时脚本(_find_dups.js 等)和报告文件

### 查重陷阱(2026-08 实测)

- **MD5 足够,不要再用 SHA256 全量复核**:MD5 碰撞在正常文件场景下不可能出现(文件都来自正常渠道)。本会话曾对 11,000+ 文件跑 SHA256 复核,15+ 分钟未完成,被判定为过度谨慎后终止——直接信任 MD5 清单即可
- **大文件组是大头**:几百 MB 的 PDF 哈希很慢,按大小分组后大文件组的哈希占绝大多数时间;可接受等待或按需分批
- **临时脚本文件要防误删**:查重脚本自身、报告文件、bat 脚本都在 PROTECT 名单里,否则可能被自己的删除流程删掉
- 大规模删除后**抽查验证**:取 2-3 个之前重复的书名,确认现在只剩 1 份

## 陷阱

- **/mnt/e/书籍 等万级文件大库:定位文件禁止 search_files 全树扫描**(2026-09-02 被用户怒斥:拖几十秒且无必要)。用 `find <限定子目录> -maxdepth 3 -name \'*关键词*.pdf\'`(秒级);内容级检索走 pdf-problem-search skill,不裸搜。
- **扫描版 PDF(纯图像,无文本层)提取不到文字**:`pdftotext` 对扫描版只输出页码/空白,没有正文(2026-09 实测 Arnold《经典力学的数学方法》= 扫描版,提取 12.6KB 全是 `===== PAGE n =====`)。**诊断方法**:提取后看输出是否只有 PAGE 行;若如此,该 PDF 需要 OCR。**解决方案见 `references/scanned-pdf-ocr.md`(Tesseract OCR 管线 + 视觉模型转写手写/扫描 PDF 的完整工作流)**。别反复重试同一扫描件。
- **解压/临时目录别留在 wiki(/mnt/e/notes)根下**: 解压外部 zip(如笔记共享vault)到 /mnt/e/notes 后,`git add -A` 会把几百个临时文件全部暂存,导致 commit 卡住/超时。流程:**先删临时目录,再 git add**;若已误暂存:`git reset` → 删 `.git/index.lock` → 删临时目录 → 重新 add/commit。
- **临时脚本放哪就删哪**: 查重/提取脚本写在 /mnt/e/书籍 或 /mnt/e/notes 根下时,用完后记得删(它们会被 git add 或重复扫描误伤)。
- **替换课程 PDF 前先核对旧文件是否更完整(2026-10 实战)**:用户说「这份替换原来那份」时,先对两份做 `pdfinfo`(页数/生成日期)+ 提取正文首尾,确认旧文件**不是更完整的版本**。实测:某课目录里旧 `topo.pdf` 是**往届完整讲义**(一直到第 17 章),而新给的 `sofar.pdf` 只是本学期进度版(前 37 页)——**静默覆盖会丢内容**。两者覆盖不同时**并存、在报告里说明,让用户定**。
- **课程材料按课归档到子目录**:讲义/习题课材料 → `<课程>/习题课讲义/`,作业 → `<课程>/作业/`(命名沿用用户下载名,如 `hw1-2026.pdf`、`2026-09-10.pdf`),与既有教材并列;别把作业散放在课程根目录,也别因"是作业"就不归档。**整门课的手写课堂笔记扫描件 → `<课程>/手写笔记/`**(按批次命名如 `2026-10-21-正课手写笔记.pdf`,与课程讲义并列);**学术讲座的报告笔记与海报截图 → `<课程>/讲座/`**(命名 `<讲者>-<YYYY-MM-DD>-<主题>.pdf` / `-讲座海报.jpg`);若该课在 `/mnt/e/书籍` 还没有自己的顶层学科目录(如概率论只有 `数学专业书籍/概率论/`),按第 2 条归到 `数学专业书籍/<学科>/`,不要为此新建顶层。
- **聊天里直接发来的讲义默认是「当轮要用」,不是归档任务**:他会无附带文字地把实验/课程讲义 PDF 发到微信,随后才说「我一会要按这个做实验」。此时直接读、直接干活,**不要顺手搬进 `/mnt/e/书籍` 并宣布「已归档」**——他会当面否掉「这东西不用归档」,而且新建的学科子目录要一并清掉。归档只在两种情况下做:材料出现在 `~/下载` 的批量流转里,或他明说要归档。需要留着查阅就放一份在 `~/下载/`。
- **下载里出现没头没尾的扫描 PDF 时,先看页数与内容再归位**:手写扫描件常常“文件名是随机数字、内容是某门课的一次课”;用 `pdfinfo`(页数)+ 首页读图确定科目与主题后,再按上面的子目录规则放;其中属于习题课(TD)的材料只归档、不进笔记(vault 侧只建概念页)。
- **判断 Office 文件内容该归哪类时,不必先装 python-docx/pptx/openpyxl**:Office XML 是 zip,直接抽文本就能定位主题(本机 python-pptx 等均未装):
  ```bash
  unzip -l f.pptx | grep -c 'ppt/slides/slide'      # 页数/体量体检
  unzip -q f.pptx -d /tmp/x
  python3 -c "import re,glob;[print(f, ' / '.join(re.findall(r'<a:t>(.*?)</a:t>',open(f,encoding='utf-8').read()))[:160]) for f in sorted(glob.glob('/tmp/x/ppt/slides/slide*.xml'))]"
  ```
  docx 换 `word/document.xml` + `<w:t>`,xlsx 走 `xl/sharedStrings.xml` + `<t>`。**要真正编辑文件**才装库;只做归类/确认内容时用这个,省一次安装。
- **一份 PDF 混了两个主题时,按内容切分再各归其位(2026-10 实测)**:用 poppler 自带的 `pdfseparate` + `pdfunite`(本机没有 qpdf/pdftk/pypdf):
  ```bash
  pdfseparate in.pdf pg-%d.pdf          # 拆成 pg-1.pdf … pg-N.pdf
  pdfunite pg-1.pdf pg-2.pdf pg-3.pdf pg-4.pdf out-A.pdf
  ```
  切分边界若落在**跨主题的那一页**(如「习题 4.3 拓扑题」与第四周 Fourier 题同页),**宁可让两份都含该页**也不要把题切丢,并在交付说明里点明哪一页是重叠页。

- **外部分享包（.rar/.zip）入库三步：先列、再解、后删源**:
  1. `unrar l 包.rar` 看清单与每项 Size（RAR5 可直接被 unrar 7.x 读）。
  2. `unrar x -o+ 包.rar 目标二级目录/` —— 压缩包自带顶层文件夹时解压出来就是目标目录，别再多套一层；解完 `du -sb` 与清单 Size 合计逐字节对齐才继续（1 GB 级包里静默少解几个文件是真实风险）。
  3. 权限会被包内属性带成 `-r--r--r--`，`chmod 644 *.pdf` 一下，否则后续要改/挪都别扭。
  4. 只有三步都过了才 `rm` 源包。
- **用户说「下载里的可以清掉了」也不等于可以盲删**:先 `find 分析 代数 物理 -iname '*关键词*'` 确认同名文件已归在课程子目录（作业在 `<课程>/作业/`、习题课在 `<课程>/TD/`），确认有副本再 `rm`；下载里的东西可能从未归档过，他说的是「这批处理完了」而不是「内容不要了」。
