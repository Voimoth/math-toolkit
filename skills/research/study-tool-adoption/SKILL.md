# 引入外部学习/AI 工具：先简报，再动手

## When to Use

用户说「我想试试 X 来辅助我学习数学和物理」「在下载之前我希望先了解一下详细信息」
「这个模型支不支持自定义插件 / 和当前系统适配性如何 / 和我的学习习惯相性如何 /
能不能和 Hermes 协同 / 有没有更好的选择」。X 可能是 AI 家教工作台、RAG 题库、笔记工具、动画器，
也可能是**一个开源模型的权重或训练仓库**（「能不能本地部署这个模型来优化某个教学 skill 的效果」）。
后者走下面「模型权重/训练仓库类」那节，判据与工作台不同。
还包括**第二个 agent（DSH / Claude Code / Codex 一类）**：「本机再装一个 agent，平时用 Hermes、有任务时让它去干」，
这类走「并行 agent harness 类」那节 —— 先对齐模型层再谈 loop，结论往往与他的预期不同。
还有「本地小模型怎么部署」「平时用小模型处理不需要思考的活、断网时顶上」—— 走「本地小模型部署类」那节，
**默认只出选型建议，不先动手装**（即使他描述的是需求而非提问）。

**本技能只管「学习/研究类第三方工具」的评估、接入与卸载**；桌面客户端选型（听歌、看图、游戏）见 `linux-gui-apps`，
本机环境/内存事实见 `linux-desktop-admin`。卸载走下面「卸载：找官方脚本，再扫五处残留」那节。

## 第一原则：他要的是简报，不是安装

他说「先了解一下详细信息」时，**不要开始 clone/install** —— 他要一份能让他自己判断的材料。
按下面**五轴**组织（这五轴就是他提问时列的那几个，缺一个会被打回）：

1. **扩展能力** —— 能不能自定义插件/技能/工具，能深到什么程度（先查官方仓库，别猜）
2. **平台适配** —— 运行时版本、磁盘、内存、许可证、要不要 Docker、有没有 GUI 依赖（Wayland 类坑）
3. **与他学习习惯的相性** —— 机制层／产出层／知识层，见下节
4. **与 Hermes 能否协同** —— 数据、记忆、调用边界
5. **有没有更好的替代** —— 至少给 2–3 个并说清各自缺什么；如果他现有的东西已经覆盖大部分，直说

**形态**：分节 + 表格 + 每节先结论后细节；他会逐条核对，含糊的形容词（「性能不错」）等于没说。

**反向也成立：说「帮我找一下 X 工具 / 找好用的 X 装上」时他要的是安装，不是清单。**
判据看措辞：**「先了解一下详细信息 / 支不支持 / 相性如何」→ 出简报等决定；「找一下…帮我装上 / 我希望用上」→
直接装推荐默认那个**，把假设与备选写进回复（他不想为“选哪个”再往返一轮）。本轮实测：说「找好用的 office 和网盘工具安装上」时只交了一份盘点表，会被拉回来重说一遍。
装的时候注意：需要交互式 sudo 的环境走图形提权（见 `linux-networking`）、大下载前先报体积，装完拿真实样本跑一次验收。

## 第二原则：先对比「已在 Hermes 里沉淀的能力」

他的学习工作流已深度绑定 Hermes：长期记忆（画像 + 学习史）、因果链教学法、引导式陪练
（状态机、不代劳）、讲义进度与作业题地图、已沉淀的卡点、wiki 铁律、一堆带 `references/` 的课程技能。
**这些都是几个月调出来的，换过去等于从零重建。**

所以结论的默认形态是：**「把它当一个工具挂在我旁边，而不是替换我」**，并给出具体分工与桥。
不要因为对方「开源／官方仓库／star 多」就替他做体验或审美决策（同类教训见 `linux-gui-apps` 的客户端选型）。

## 相性核查清单（三问，缺一不可）

- **机制层**：它能不能表达「引导式陪练、不代劳」？——只有提供 SKILL.md / persona / system-prompt
  注入类机制的才能做到，纯 RAG 问答机器人做不到。
- **产出层**：它的产出能不能落进 `/mnt/e/notes` 那个 Obsidian vault 的格式？
  （一概念一文件、禁 emoji、概念页只写概念本身、理论力学平铺、法国记号如转置 t 写左上角）
  ——通用工作台**不会**知道这些，要么写进它的 persona，要么只能「它出内容、Hermes 落盘」。
- **知识层**：他的 PDF（袁业飞讲义、Arnold 习题、扫描件）能不能喂进去做 RAG？
- **产出型工具另加三问**（动画/可视化/图示生成，如 manim、p5.js）：它的产出不是对话而是一个文件，所以 ——
  ①**产物落在哪**：vault 只收 md（外加 git-hooks），视频/网页必须在 vault 之外另找位置；
  ②**制作时机**：要写脚本 + 渲染的工具进不了「一轮一个问题」的节奏，只能当**课后离线切片**，不能插进答疑主线；
  ③**会不会代劳**：动画只能演结构、不给结论 —— 把结论演完就等于「替他想」，违反陪练铁律。
  纯交互式（拖参数看变化）与烘焙成视频是两条不同的路，前者每次要开浏览器，后者可回看但不交互。

## 模型权重/训练仓库类：先判底座，再判显存

「本地部署这个模型能不能提升辅导效果」的答案几乎总是分两层，先给结论再给数：

1. **微调/RL 改行为，不改能力。** 先从 HF 模型卡的 `base_model:` 标签（或 `api/models/<id>` 的 tags）
   读出底座。教学型微调的底座若是 7B（Qwen2.5-7B-Instruct 一类），数学能力天花板就是那个底座；
   论文自身对 GSM8K/MATH500 的措辞通常是 **maintain**（维持）而非提升。所以「换个教学微调 7B 让辅导更强」
   在能力层是零收益——它优化的那套行为（先问、不给答案、话短）多数已经写在本地 skill 的提示词里。
   他有过「本地 7B 做数学太弱」的先验，别用新名字重推同一档位。
2. **显存硬定可部署档位，先量再算。** `nvidia-smi --query-gpu=memory.total,memory.used --format=csv`
   ＋ `free -h`，算出「权重＋KV」是否装得下。本机 8 GB 级显存的实测口径：9B 的 Q4_K_M 是 5.68 GB，
   「装得下」但没余量（KV 加桌面合成器就溢到内存、掉到个位数 tok/s），**4B（2.74 GB）才是舒适档**；
   12B 级起直接判死。
3. **训练类仓库按 config 算卡。** 看 `config/**/*.yaml` 的 `number_of_gpus_per_instance` 与
   `gpu_memory_utilization`：多角色（teacher/student/judge 各占 4 卡）＝ 12 张 80G 级卡，本地直接判死。
   这种情况明说零可能，不要给「精简一下也许行」的模糊话。
4. **默认结论形态是「抄提示词，不抄权重」。** 这类仓库的价值多在 `prompt_templates/`（system prompt、
   判分模板）与 reward 设计：纯文本、语言无关、可挂到现有 API 模型上零成本试（典型用途是做**课后自检**——
   独立复查「这轮我是在陪练，还是替他把题做掉了」）。搬模板时留意它自带的语言限制（英文专训的 judge
   会把「语言混用」判 REJECT），中文/法语场景要换掉那条与样例。
5. **硬数据一次查齐**：repo 是否 fork / stars / 最后 push、HF 的 downloads / likes / lastModified、
   底座与 license（README 与模型卡常不一致，分别标明出处）、有无第三方 GGUF 量化及其精确体积。

取数配方（HF 元数据与文件大小、整仓 tarball、按档位量化体积表、后训练显存与 LoRA 目标模块）
见 `references/local-open-model-eval.md`。

## 后训练/微调能不能「调成需要的样子」

他接下来一定会问这个。先给一句结论再给数：**能，但本机只有「4B + QLoRA(4bit)」这一种组合成立，
而它能改的恰好不是他最想要的那部分。**

- **显存档位（QLoRA，估算；报数时必须标「未实测」）**：2B 宽松（seq 4k、batch 2）；
  4B 可行但就是上限（seq 2–4k、batch 1 + 梯度检查点）；9B 不行；**GRPO/RL 任何档位都不行** ——
  它要 policy + reference 双份权重再叠 rollout 显存。
- **SFT 改行为，不改能力**（上节第 1 条的推论）：格式、纪律（不代劳、一轮一问）、记号与拒答模式学得会；
  「讲清数学史动机」「看出证明第几步跳了」「Arnold 级题正确率」学不会。他的核心需求属第二类 ⇒
  直说「这类收益近零」，别包装成「微调后会更懂你的教学法」。
- **SFT 唯一真收益**：不必每次塞两千 token 的 system prompt —— 省 context、让 4B 在小任务上输出稳定。
  收益是真的，但按这个量级说，别夸大。
- **最贵的一项不是 GPU 是数据**：改行为要 500–2000 条高质量样本，只能强模型按本地 skill 生成 + 人工筛；
  本质是把强模型的文体蒸馏进 4B，天花板仍是 4B 底座。
- **上线闸门：先做零成本那一步。** 拿 20 个他真问过的问题，套严格 system prompt + 两三条 few-shot 跑一遍，
  按错的类型分流：**格式不稳 / 爱代劳 / 啰嗦 ⇒ 值得 SFT；讲错 / 看不出跳步 ⇒ 别训，训了也一样**
  （与他「本地 7B 数学太弱」是同一个判据）。跳过这一步直接给训练方案 = 替他花几小时买零收益。
- **混血架构的 LoRA 目标模块要显式点名。** 新代小模型（如 Qwen3.5 的 32 层里 24 层是 linear attention）
  若 target_modules 只写 q/k/v/o_proj，只训到四分之一层、其余梯度绕不过去；必须连线性注意力层的投影一起列，
  并装 flash-linear-attention（FLA）类依赖。清单与体积见 reference。
- **训完回部署要三步**：LoRA 合并（`merge_and_unload`，在 16bit 底座上做）→ `convert_hf_to_gguf` → 再量化。
  几十 MB 的 adapter 本身 llama.cpp 直接吃不了，别说成「训完就能用」。
- **他已经判过「后训练性价比不高，不考虑」—— 不要再主动提训练方案。** 只有他自己重新问起时才按上面的闸门答，
  且仍然先过「零成本那一步」，不要因为换了个更强的底座就重开这一题。

## 本地小模型部署类：默认出建议，不先动安装

触发：「我想了解一下本地模型的部署」「我希望平时能用小模型解决一些不怎么需要思考的问题，偶尔断网也能代替一下」。

**即使措辞是需求陈述，默认产出仍是「选型建议 + 真实体积/显存数字 + 末尾一句 go-ahead」，不是先 pacman/install。**
判据是量级差异：本地模型是 2–5 GB 下载、可能顺带装一个 systemd 服务，比「装个 GUI 客户端」重一档，
他会直接打断说先给建议。只有显式「帮我装上 / 装一个」才动手，动手时按上面「反向也成立」那段的规矩来。

**它的合理定位（他给定的需求）：低思考任务 + 断网替身，不是数学辅导。** 先按这个定位给结论，别把 4B 包装成辅导助手。
- 值得接的活：中法数学术语对照、md/LaTeX 格式互转、文件与壁纸批量命名初筛、短摘要、正则/shell 片段、离线草稿。
- 不适合：证明检查、概念动机讲解、长讲义结构化 —— 照旧走云端（判据同「微调改行为不改能力」）。
- **断网边界必须主动说清**：本地端点（Ollama `:11434/v1`、llama-server `:8080/v1`）能接成 Hermes custom provider，
  但 4B 的 function calling 撑不住多步工具循环 ⇒ 断网时它替代的是「一个聊天模型」，不是「我」。
  不说这句，他会以为断网还能让我跑脚本改文件。

**「有没有针对我场景特化的小模型」——三类分别判，别混成一档：**
- 数学特化（RL 强化数学的 7B/8B、R1 蒸馏系、各种 GRPO 版本）：底座基本还停在上一代（Qwen3-8B / Qwen2.5），
  **比当代同价位的通用 9B 更弱 ⇒ 不装**。查特化模型时第一判据是 `base_model:` 的代次，其次才是训练配方。
- 教学/教育微调（EduChat 一类）：改的是「怎么说话」，与本地 skill 提示词重复 ⇒ 不需要它的权重。
- 文档/公式 OCR（dots.ocr 1.7B、PaddleOCR-VL、DeepSeek-OCR-2）：**唯一有确定收益的一类**，
  产出物明确、可验收，且正好补 tesseract「正文可读、公式不可靠」的缺口。要推就推这一类。

档位体积、后端选型、上下文算术（KV 只按 full attention 层算）与 HF/Ollama/GitHub 取数配方见
`references/local-open-model-eval.md`。

## 并行 agent harness 类：先对齐模型层，再谈 loop

「再装一个 agent（DSH / Claude Code / Codex 一类）补我的短板，由 Hermes 调度它干活」是独立的一类，要分三层回答，缺一层就会替他做出错误预期：

1. **模型层是天花板。** 两边挂同一个模型时，「换 harness 让数学/代码更强」在能力层是零收益 —— 真正的差在 loop：
   plan mode、diff review、subagent 编排、trajectory 回放、PTC（模型写一个程序来编排多步工具调用）。
   结论默认形态：**值得为代码活加，不值得为数学活加**；数学卡点在引导方式与概念链，换 loop 管不到。
   所以先问一句「两边各用什么模型」，比通读它的 README 有信息量。
2. **协同接口首选 headless CLI，不要 GUI 自动化。** 判据与上面「协同」一节相同，再加两条：它有没有一次性运行模式
   （`<tool> --profile headless "任务"` 一类，结果走 stdout、`--json` 出事件流、能续会话）；以及**它在本平台有没有原生构建** ——
   这类产品常只发 win/mac 桌面版，Linux 只剩 web/headless profile，别按「装个桌面版让我去点」设计流程。
   同理，让它的技能树读 Hermes 的 `skills/`，优先找官方 filesystem provider（带 `customSkillDirs` 一类配置），别自写共享插件。
3. **环境变量会串味。** 从 `HERMES_HOME/.env` 喂 key 给外部 CLI 时**只取需要的那个变量**：
   `set -a; . .env` 会把 Hermes 自己的语义整套注入（例：`DEEPSEEK_BASE_URL` 在 Hermes 里是裸域名，
   而别的工具期望它含完整 API 前缀 → 拼出 `/messages` 打 404）。取法：`api_key=$(grep -E '^DEEPSEEK_API_KEY=' "$HERMES_HOME/.env" | cut -d= -f2-)`。
4. **报「可行」之前要三条硬数据**：装完体积、装耗时、一次真实任务墙钟；跑通再下结论。
   平台支持别只信文档（README 常只说桌面版），在 scratch 里装一份、跑一次真实入口，才知道 CLI 到底能不能用。
   探针放 `$HERMES_HOME/cache/scratch/`，验完立即删 —— node 类工具链动辄 800MB+，别留在他盘上。
   **删之前先离开那个目录**（`cd` 走或给终端命令显式传 `workdir`）：把会话当前目录删掉后，后续每条命令都会以
   `cd: … 没有那个文件或目录`（exit 126）失败，因为 shell 包装器每次都会恢复 cwd。

5. **「模型在自家 harness 上更强」这类说法要读请求构造，别信印象。** 拉它的模型适配包，看发给同一家 API 的请求比第三方多什么：
   典型只有归因 User-Agent 与 `*-session-id` / `*-compact` 一类标记，那是对账与压缩分流用的，**不构成质量特化证据**。
   若差异真存在，机制只能在脚手架侧（system prompt 写法、工具粒度、compaction 策略、reasoning effort 默认档），
   **那是可以 A/B 的，要把话说成「待测」而不是「更强」**。取子包源码要**锁版本**（`npm pack <pkg>@<ver>`）——
   多包 npm 产品各子包的 `latest` tag 并不同步，混着读会得出过时结论。

DSH（DeepSeek Harness）的 Linux 命令、profile 清单、404 根因与技能共享配置见 skill `dsh-shared`。

## 平台适配：先量，别猜

一条命令拿本机事实，再照着填表：`python3 -V` / `node -v` / `free -h` / `df -h /` / `command -v docker`。

- **本机系统 Python 版本很新，而多数 AI 工作台钉在 3.11–3.13** —— **不要动系统 Python**，
  用 `uv python install <ver>`（本机已有 `uv`）等隔离版本装。
- **没有 Docker 时优先本地 venv / CLI-only 安装**：比容器轻，也更省内存。
- **资源要算进预算，但别按 Windows 时代的节俭标准砍方案。** 这类工作台前后端一起跑通常吃 1–2G，
  装之前把这个数报给他（排查见 `linux-desktop-admin` 的内存诊断那一节）。
  换成 Linux 后他明确说过「可以不用那么节俭，只要在会话结束的时候清理一下就行」——
  一次性装几百 MB、后台跑一小时都能接受；真正不能碰的边界是**别留常驻受管进程、别占满 CPU 影响他学习**，
  收尾把探针、临时目录、测试会话日志清干净。判断按当前系统说话，不要拿旧环境的标准替他省钱。

## 协同：优先挑 CLI-native + 结构化输出的工具

判据只有两样：**命令行能不能一次跑完一种能力**、**输出有没有 JSON 模式**。
两者都有，Hermes 就能直接调它（如 `<tool> run <capability> "…" --json`），拿回结果后按上面的产出层规则落盘；
都没有，就只能人工在两个界面之间搬，价值大打折扣。
另有一条容易被忽略的：不少这类项目会**自带一份给 agent 看的 SKILL.md**（「交给任何有工具的 agent，它就能自主操作本工具」）
—— 有这个东西就是明确的可集成分，看到就标出来。

## 收尾

- 报「已核实 X ／ 未验证 Y」。**没装过就不要把安装步骤写成「已验证的流程」**，标明来源是官方文档。
- 他决定装了再动手；装完**拿一个他真实的材料跑一次**（例如讲义某一章），
  用真实输出和他 wiki 里已沉淀的内容对照，而不是描述它「应该能做什么」。

## 卸载：找官方脚本，再扫五处残留

用户说「卸掉刚装的 X」不是「删了目录就完」，按这套：

1. **先读它自带的 uninstall 脚本再用**，别手删。`ls <安装目录>/scripts/` 常带 `uninstall-*.sh`。默认档多数只删派生命令、**保留 config 与 credentials（含 API key）**，要 `--purge` 才连配置一起清；它还会按带标记的块自动清 shell rc 里的 PATH 片段，比手 grep 稳。读完再跑，不盲执行。
2. **手删它没覆盖的残留**，重点五处：
   - CLI 自己的用户配置与状态：`~/.<工具名>`、`~/.<工具名>.json`（常含 onboarding、历史、备份子目录）；
   - 启动项：`~/.local/share/applications/<…>.desktop`、`~/.config/autostart/`、`~/.config/systemd/user/` 单元；
   - shell rc：`~/.zshrc` / `~/.bashrc` / `~/.profile` / `~/.config/fish/config.fish`（fish 写的是 `set -gx PATH`，不是 export）；
   - 自装运行时：这类客户端常把 node 与 CLI 本体塞在 `~/.<工具名>/node` 里，删安装目录就一并清掉 —— 真判据是 `command -v <它的命令>` 变空，不是目录在不在；
   - 浏览器侧：Firefox 的 `~/.config/mozilla/firefox/<profile>/storage/default/https+++<domain>`（站点存储，属浏览器数据，报一句即可）。
3. **别把同名技能当残留删**：`~/.hermes/skills/**`、`~/.dsh/skills/**` 里以工具名命名的目录（如 `claude-code`）是给 agent 看的文档，与安装无关。

**破坏性动作前备份并声明何时清**：把 config/key 拷到 `$HERMES_HOME/cache/scratch/<工具>-backup-<日期>/`（scratch 24h 自动清），回复里给路径。核备份要用 `ls -la`——`ls`/`ls -R` 不显示 `.claude.json`、`.claude` 这类隐藏项，容易误判成没备成功。

**验证交给 DSH 做只读复核**（这类活按分工本来就该 DSH 起手，见 skill `dsh-shared`）：给它一份固定清单——文件系统扫描（排除 `.hermes`/`.dsh`/`node_modules` 等别的软件自己的文档）+ `command -v` 三个变体 + 五个 rc 文件 grep + 进程/systemd/desktop + 历史条数，要求逐条带路径证据、只读不删；报告里标「DSH 复核得」。同一套检查我自己再跑一遍不算第二证据。

## 装完之后：核验它到底进没进工作流

装完不等于用上。他问「用了一段时间，你有感觉到什么提升吗」时，**先去会话库数调用次数，别凭印象答，也别拿技术指标充收益**。

```bash
python3 - <<'EOF'
import sqlite3, datetime
c=sqlite3.connect(f'file:{__import__("os").path.expanduser("~")}/.hermes/state.db?mode=ro',uri=True)
for name,p in {'新工具':'%<新命令>%','旧主力':'%<旧命令>%'}.items():
    rows=c.execute("select timestamp from messages where tool_calls like ?",(p,)).fetchall()
    days={}
    for (t,) in rows:
        d=datetime.datetime.fromtimestamp(t).strftime('%m-%d'); days[d]=days.get(d,0)+1
    print(f"{name} 共 {len(rows)} 次 {dict(sorted(days.items()))}")
EOF
```

（`messages.tool_calls` 是 assistant 消息里的工具调用 JSON；按天分组就能看出是不是集中在「安装当天自测」。）

判据与处理：

- **调用全部集中在安装当天 ⇒ 它没进工作流，收益是 0**，不管基准指标多好。要直说「没用上」并给原因，
  别用「效果一般」糊过去；也**别把「没进工作流」与「进了但效果差」混为一谈**。
- 两个常见原因：①**触发面太窄**（它的定位是「跨库找」，而他实际的问题形态是「已知书、缺页码」）；
  ②**产物形态与他的交付要求冲突**（RAG 给「书上怎么写的」，他要概念动机链，且明令禁止把检索结果改写成总结——
  所以即使检索到也不会那样用，工具与产物不在一条线上）。
- 五种处置：①**收窄触发规则并写进那个技能的正文**（不能只写在 references）；②**留而不投维护**，明确「不会主动检索」；
  ③删掉重来（先算重建成本再提议）；④**换粒度重建**；⑤**改产物形态**（见下两条）。
- **拆工具之前，先把「需求」和「这个实现」分开问一遍。** 空转的常常不是需求，是**粒度选错了**：
  页级全文索引没人用，而「想查哪本书讲过 X」的需求是真的 ⇒ 换成**书目级**（只读书名/作者/书签目录，不抽正文），
  一次性成本从「几小时 + 几十 GB」降到「十几分钟 + 二十几 MB」，且扫描件只要带书签也能命中章节。
  选粒度的问法是：他的提问停在哪一层——「哪本书」是书目级，「哪一章」是目录级，「哪一页哪一句」才要页级全文。
  多数情况下人根本走不到第三层，先建第三层就是白花。
- **换到书目级之后，两个设计决定它到底好不好用。** ①**目录页兜底**：书签只覆盖四成左右，剩下的按成本分层补——
  有文本层就直接取前 20 页（精确、零成本），扫描件走 tesseract（英文印刷体近乎逐字对，中文能认出章节行但带错字，
  对「搜索召回」够用、对「当目录读」不够，150 dpi 下约 18 秒/本），**只有 OCR 也读不出的少数才值得上视觉模型**：
  一万多页扫描目录逐页看图既贵又慢，而中文错字对召回并不比 tesseract 差。OCR 文本只参与匹配、**不进结构化目录**，
  输出必须标「目录页命中，自己去翻」——冒充章节页码会让他按错页去翻。②**层级权重**：他的书库有天然优先级
  （课程在用 > 预科/配套讲义 > 普通参考书），排序用 `score *= 1 + k*(tier-1)` 而不是加分——
  加分会让低分书被层级硬顶上来，查课程书里根本没有的词也会冒出来。tier 应来自路径规则（根目录 + 路径片段），
  不要靠人工打标，否则新增书就漏。
- **报覆盖率/本数之前，按最新库重算一遍。** 删过垃圾文件、跑过增量之后旧统计就废了；他记得住上一轮的数字，
  差一个数会被当场对出来。同理，「第几层覆盖了多少本」这类数只能拿当前库 `count(*)` 说，不要用手算。
- **产物形态与交付要求冲突时，命中率再高也不能用。** 一个只能给出「书上怎么写的」的检索器，
  对他的概念动机链教学法是反向的（他明令禁止把讲义/检索结果改写成总结）——这类冲突要在报告里直接点名，
  别把它包装成「效果好但用得少」。
- **重建或换形态后，用真实查询验收，给命中样本而不是统计量**：几本书名 + 章节标题 + 页码，
  他一眼就能判断有没有用；只给「命中 N 本」「覆盖率 X%」等于没验。同时把修掉的假阳性/假阴性
  一并报出来（噪声命中的典型来源：只写前缀的词边界、封面版权页的目录条目、平台垃圾文件）。
- **「容量」类能力最容易空转**：索引、缓存、预建库建好不用就是零，还要付**过期成本**（索引不自动更新，
  拿旧快照检索会得出「书里没有」这种错误结论）。这类东西尤其要先问「什么具体提问才会走到它」。
- **接入后的长任务，进度只认进程自报。** 批处理脚本要自己每 N 条打一行百分比并 flush；别用副作用反推——
  DB `count(*)`、目标目录文件数都受 commit 间隔影响，会好几分钟不动、看着像卡死。这个误判在同一个会话里犯过两次
  （一次判成「2 本/秒要跑 1 小时」，一次判成「进程停了」，实际都在正常跑）。Hermes 的后台任务用 `process_manage`
  `action=poll` 读它自己的输出；`ps` 的 ELAPSED/CPU 时间同样不能当运行进度看。抽样外推也不可靠：
  30 本 × 100 ms 外推 13.5 分钟，实跑 666 秒——文件大小分布右偏，平均值代表不了长尾。
- **并发数按机器余量定，不按核数。** 6 并发 tesseract 已能让 16 核跑到约 170% CPU；长任务挂后台时不能占满，
  他还在这台机器上学习。给 timeout ＋ 并发上限，跑完即退、不留受管进程。

## 外部技能包/分享包类：先量分布，再挑「纯规则文本」

他丢来一个别人分享的 skill 包（如 `pika_math_learning_toolkit-<ver>/payload`）问「有什么可借鉴的」时，
**不要逐个文件读**（几百个文件、几 MB，读不完也读不起）。按这个顺序：

1. **先量分布**：`find . -type f -printf "%8s  %p\n" | sort -k2` ＋每个子技能的文件数/总字节。
   判据：**一个子技能 `scripts/` 占几百 KB 而 `references/` 只有几十 KB ⇒ 那是重型基建，可借鉴度低**。
2. **读 `references/` 的「文件名」就是读主题表** —— `natural-chinese-lint.json`、`editing-protocol.md`、
   `query-normalization.md`、`search-evaluation-contract.md` 这类名字直接暴露可搬的东西，不开文件就能先排掉 90%。
3. **优先搬「纯规则文本」**：lint 规则集、判据/契约、编辑协议、状态机规范、评测用例 —— 零依赖、当天可用；
   其次是「借思想」（把机制翻译成本地规则，如「结论门」「上下文预算」）；最后才是权重/服务/整套基建。
4. **明确列「不搬」及理由**：平台运行时（Windows/外挂）、打包耦合清单（`version-coupling-manifest.json`
   这类 10–100KB 的 JSON）、他们自建的观测框架、为无状态 agent 加护栏而存在的 KB 服务 —— 与 Hermes 的
   skills+memory+vault 重复，搬进来只增加维护面。
5. **顺手做一次安全扫**：`grep -rhoE "https?://[a-zA-Z0-9._-]+" <包>` 统计出网域名 ＋ 搜 `api_key|token=|telemetry`。
   全是 `example.com`/`127.0.0.1`/测试桩 = 本地 CLI，可以照用；有真实上报端点必须先说清。
6. **交付形态**：三档清单（可搬 / 借思想 / 不搬），每条给**文件路径 + 它解决什么 + 落到我哪个技能**。
   搬过来的英文规则要改成中文/本机语境（例：英文 judge 的「语言混杂」判据在中文＋法语术语场景会恒判失败）。

个案（pika 数学学习工具包六个子技能的资产坐标与落点）见 `references/pika-math-toolkit.md`。
