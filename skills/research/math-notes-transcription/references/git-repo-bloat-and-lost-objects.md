# Git 仓库膨胀诊断与孤儿对象找回（/mnt/e/notes 实战 2026-09-11）

## 触发场景

用户说「notes/vault 里好像有不少冗余文件」，但工作区看起来很小；或你发现 `.git`
体积远大于工作区内容。**本例 `.git` = 159 MB，而笔记本体只有 1 MB。**

先记住结论：**这类膨胀通常根本不在工作区里**，工作区扫得再细也找不出来，
必须去 `.git/objects` 里查。

## 一、诊断三步（全部只读，先别动手）

### 1. 量总账

```powershell
git count-objects -vH
```
关注 `size-pack`（打包体积）、`in-pack`（对象数）、`garbage`（有则说明上次操作中断过）。
本例输出 `in-pack: 1198 / size-pack: 158.05 MiB / garbage: 1`。

### 2. 列出 pack 内最大的对象

```powershell
git verify-pack -v .git/objects/pack/pack-<hash>.idx
```
输出每行字段：`SHA1  type  size(未压缩)  size-in-pack  offset  [depth base]`。
按第 3 列排序即可拿到大对象。

**不要**用 `git rev-list --objects --all | Select -First 3000` + 逐对象 `git cat-file -s`
去查大小——本次这么做**得到错误结论**（以为最大只有 0.42 MB），因为①有截断
②PowerShell 里 `git cat-file` 易静默失败。**直接上 `verify-pack`。**

### 3. 判定可达性（权威判据）

```powershell
git fsck --unreachable --dangling
```
- `dangling blob` = 完全无引用（典型来源：`git add` 后 `git reset`）
- `unreachable blob` = **仅被 reflog 吊着**（典型来源：`commit --amend` / `rebase` / 历史重写）

这个区分很关键：**unreachable 的对象不会因普通 `git gc` 被回收**（reflog 还在引用），
必须先 `git reflog expire`。

## 二、交叉验证（必做，别凭单一脚本下结论）

取一个**当前工作区文件的 blob**，确认它**不在**那个大 pack 里：

```powershell
$cur = git hash-object '数学/代数/代数III/笔记/代数III笔记.md'
git verify-pack -v <idx> | Select-String $cur    # 应无输出
```

本例：pack 内 1110 个 blob 全部 unreachable，当前文件的 blob 不在其中
→ 那个 157.8 MB 的 pack 是**零可达对象的纯垃圾**。

再补三项健康检查排除误判：
- `git branch -a` —— 确认没有别的分支可能引用那些对象
- `git remote -v` + 本地/远程 HEAD 比对
- `Test-Path .git\shallow` —— 浅克隆会让可达性判断失真

## 三、清理前的安全检查（缺一不可）

1. `git fetch origin`，然后比对 `git rev-parse HEAD` 与 `git rev-parse origin/main`
   —— **必须完全一致**（不一致就先 push）。本例两边都是同一 commit。
2. `git status --porcelain` 干净。
3. **把 >1MB 的孤儿对象导出到仓库外**当安全副本（见第四节），再考虑删除。

## 四、导出孤儿对象（二进制安全，两个坑）

⚠️ 坑 1：`& cmd /c "... > file"` 会被 Hermes 网关判为 `&` 后台运算符而**拒执行**。
⚠️ 坑 2：PowerShell 管道接 `git cat-file` 会把二进制变成字符串 → **文件损坏**。

✅ 可靠做法：`Start-Process -RedirectStandardOutput`（写出原始字节）：

```powershell
Start-Process -FilePath 'git' -ArgumentList "cat-file","blob",$sha `
  -WorkingDirectory '/mnt/e/notes' -RedirectStandardOutput $outfile -Wait -NoNewWindow
```

批量导出：先 `git verify-pack -v` 拿到 `sha → size` 映射，筛出 >1MB 的，
逐个导出到 `~\Downloads\<repo>-lost\`（纯 ASCII 路径，仓库外）。

## 五、识别（孤儿对象没有文件名，只能按魔数判断）

| 魔数（前几字节） | 类型 |
|---|---|
| `FF D8 FF` | JPEG |
| `89 50 4E 47` | PNG |
| `47 49 46 38` | GIF |
| `00 00 00 .. 66 74 79 70`（含 `ftyp`） | MP4/MOV |
| `50 4B 03 04` | ZIP（含 docx/xlsx） |
| `25 50 44 46` | PDF |
| `52 49 46 46` | RIFF（WEBP/WAV） |

尺寸辅助判断来源（`System.Drawing.Image` 读 Width/Height）：
- `6240x4160` / `3264x2448` → 手机摄像头照片
- `1920x1080` / `1536x1024` / `2816x1536` → 屏幕截图
- `3136x3138` / `2045x1365` → 扫描件或文档拍照

**文本类**：读前 200 字节看内容。本例召回了三类「非图片但同样没用」的泄漏源：
- Obsidian 插件打包产物（`/* THIS IS A GENERATED/BUNDLED FILE BY ESBUILD */`）
- 内嵌 base64 字体的 `styles.css`（`@font-face { font-family: cmb10; src: url(data:font/...)`）
- 一张 SVG 示意图（来自某次会话产物）
→ 说明`.obsidian/plugins/*/main.js` 与 `styles.css` 曾进过版本库，`.gitignore` 只忽略
`.obsidian/` 的当时状态并不彻底。

导出后**按类型改名**（加正确扩展名），交给用户目检决定去留。
**绝不自行删除可能是用户照片的对象**——它们是 unreachable，删了就永久没了。

## 六、清理（用户确认后）

```powershell
git reflog expire --expire=now --all   # 先放掉 reflog 引用
git gc --prune=now                     # 再回收不可达对象
```

- `git gc` **绝不删除可达对象**，风险仅限于丢失 reflog 的撤销能力
  （已 push 到远程时可忽略）。
- 本例 `.git` 159 MB → 约 2 MB。
- 跑完回读 `git count-objects -vH` 与 `git log --oneline -3` 确认历史完好。

## 七、预防（2026-09-11 已全部落地）

**这些措施在该 vault 上已经实装完毕**，换机器时需重建（vault 侧状态见 `math-physics-wiki` 技能的「git 卫生与 .git 膨胀」一节）：

1. **`.gitignore` 大文件格式**（已加）：
   ```
   *.mp4 *.mov *.avi *.mkv *.flv *.wmv *.gif
   *.zip *.7z *.rar *.iso *.exe *.msi *.dmg
   *.heic *.raw
   ```
   另加 `共享/scripts/pdfjs/*.pdf`（临时讲义副本）、`wikilinks.md`（Obsidian 反复自动生成的 0 字节产物）。
2. **`pre-commit` 钩子拒绝超过 5 MB 的文件**（已加）：活动位置 `.git/hooks/pre-commit`，存档 `共享/git-hooks/pre-commit`。
   - 必须**实测**：造 6 MB 文件 → `git add -f` → 试提交 → 确认退出码非 0 且提交数不变。
   - ⚠️ **测"放行"边界（如 4.9 MB）会真的产生一个提交**（2026-09-11 我在这栽了：提交数 81→82、HEAD 变了、`_v2.bin` 进了仓库）。测法：`git rev-list --all --count` 记下基线 → 试提交 → 无论结果都 `git reset <基线commit>` 撤掉 → 复查提交数/跟踪文件数/`git status` 回到基线 → 跑 `reflog expire + gc --prune=now` 把产生的孤儿 blob 也回收掉。**若已 push 则不能用 reset 撤销**（会与远端分叉），务必在测试前确认没 push。
   - 两个实现坑：①读 diff 列表必须加 `git -c core.quotepath=false`（否则中文文件名被八进制转义、路径匹配失败）；②用 `while read < 临时文件` 而非管道（管道内变量传不出子 shell，拦截标记会丢）。
   - 配套 `.gitattributes` 写 `共享/git-hooks/* text eol=lf` —— 否则 git 会把钩子的 LF 转成 CRLF，sh 报 "bad interpreter"。验证：`git check-attr -a <路径>` 应显示 `eol: lf`，再用 `Start-Process git cat-file blob <sha> -RedirectStandardOutput` 数 CR 字节应为 0。

**注意 `.gitignore` 的失效陷阱**：原规则写的是 `scripts/pdfjs/extract.js`，而实际路径是 `共享/scripts/pdfjs/`，
**无前导斜杠但含斜杠的模式只相对 .gitignore 所在目录匹配**，所以该规则从未生效。写 ignore 规则后要用
`git check-ignore -v <路径>` 验证真的命中。

## 八、本例根因（可供类比）

该 vault 曾被误 `commit` 进手机照片（26MP）、屏幕截图、动图、MP4、Obsidian 插件打包文件，
随后有人重写历史移除它们——blob 留在了 pack 里被 reflog 吊着，形成 157.8 MB 死重。
**工作区完全看不出来**：`git status` 干净、`git log` 正常、文件只有 1 MB。
