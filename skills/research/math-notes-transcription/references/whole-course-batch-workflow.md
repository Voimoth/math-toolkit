# 整门课（100+ 页）手写笔记入库：分段并行 + 习题课「提炼」（2026-10-03 代数 I 实战）

输入：正课 113 页 + 习题课 69 页（CamScanner 手写扫描件，中文正文＋法语术语，原生 264–294 ppi）。
产出：正课 41 篇笔记 + 习题课 25 篇 + 175 概念页。耗时：转写约 25 min，整理 2 批并行约 8 min/批。

## 步骤

1. **转图 300 dpi**（先 `pdfimages -list -f 1 -l 1 in.pdf` 看原生 ppi：本例 ≈264–294，300 dpi 刚好不过度；再高只是插值）。
2. **批量视觉转写**（`scripts/vision_transcribe_batch.py`，正课/习题课各开一个后台进程并行）。**起多个并行后台进程时写 `cmd1 & cmd2 & wait`，不要给每个命令套 `( … & )` 子 shell**——子 shell 会让外层 shell 立即判为执行完毕、tracked session 变 exited、完成通知丢失（进程其实还在跑，但脱离管理，只能自己轮询进度）。
3. **机械清洗**：删页脚水印（扫描全能王）、删页首模型元评论行、`\(`→`$`、压空行。
4. **先切块、再派活**：按主题把整份稿切成 7–15 页的小块文件（`zk_A.txt`…/`tk_A.txt`…），每块带头部 `===== pNNN =====` 页标记。**不要让子代理各自从整份大稿里找自己那段**。
5. **写一份统一规范文件**（放 agent 工作目录，如 `~/.hermes/cache/<proj>/整理规范.md`），子代理第一步 `read_file` 它——**不要在 10 个 context 里重复粘贴规范**（易漏易漂移）。内容：背景/输入输出路径/笔记 frontmatter 模板/callout 映射/概念页规则/**笔记篇末概念链接段与概念页出处回链这两向要求**（见 `wiki-content-and-formatting-rules.md`）/纪律/收工汇报格式。
6. **派子代理**（≤10 并行，本例正课 10 段、习题课 7 段）；每段 context 只给：转写稿路径、页范围、原图目录、篇章编号区间、本段主题与特别注意。
7. **父代理收尾**：断链扫描（`[[...]]` basename 比对）、坏模式扫描（`\xlongequal`/`===`/粗体标签/emoji）、写 `00-总览.md`、更新学科 `_索引.md`、追加 `log.md`、`git add/commit/push`、删中间产物（页图几百 MB）。

## 关键教训

- **子代理会把 delegation 模型拖进「唱歌」死循环**：长机械会话用非思考路由——`hermes config set delegation.model deepseek-chat`（provider 同样可设）。本例 10+7 个子代理全程无死循环。
- **子代理会自行「修正」公式，父代理必须回原图复核**：代数 I p014 的 ℚ 构造，转写稿把 `+`/`×` 两行的连接符都写成 ×，子代理按数学改对了；父代理回原图核对后确认「右侧公式正确 + 原稿确实两行都写 ×」，才敢下结论。**凡子代理汇报里带「我动了公式」的条目，逐条复核**。
- **同义/同名概念页重复是必然的**：不同子代理分别建出 `素元.md` 与 `素元素.md`、`中心与中心化子.md` 与 `群的中心.md`。父代理收尾要按同义/上下位关系**去重合并并改链接**（本例删 2 页、改 5 处链接）。**`write_file` 的撞名守卫只挡同名文件，挡不住「同一概念、不同 slug」**（实测 `denombrable`/`denombrabilite`、`continuite-de-la-probabilite`/`continuite-des-probabilites`）——收尾要按**概念**而不是按文件名查重；同时分辨真重复与「名字相近其实是两个概念」（`espace-probabilisable` $(\Omega,\mathcal{F})$ 与 `espace-probabilise` $(\Omega,\mathcal{F},\mathbb{P})$ 不能合并）。合并时保留内容更全的那一页、把另一页独有的段落并进去，再全局改链接。
- **子代理命名漂移是常态**：同一批子代理产出的文件名/标题风格不一（连字符 vs 空格、带不带重音、中法混排）。父代理收尾统一到单一约定（本 vault：**ASCII 连字符，去空格/逗号/撇号/重音**），并用脚本同步每篇 frontmatter 的 `title` 与指向它的链接；`00-总览`、`_索引` 一律用统一后的名字写。
- **跨课程同名冲突无法在批内解决**：代数 I 与代数 III 各建了 `群`/`商群`/`正规子群`/`同构定理`/`导群`/`群作用`/`模` 七对同名页 → `[[群]]` 短链接在 Obsidian 里歧义。批内用 `search_files` 防覆盖只能防同批，**跨课程冲突要报告用户决定**（合并成一份 / 改用带路径链接）。
- **收工汇报要固定格式**（文件清单 / 页覆盖 / 存疑点 / 一句话概括），父代理才能直接拿来写总览、索引与存疑点清单。
- **概念页数量参照**：一门课 175 个偏多，其中基础概念（`空集`、`子集`、`断言`）可考虑合并——交付时把清单给用户，让他定（用户要「手动覆盖入口」）。

## 只转写不整理时的分片（只产出转写稿、不写笔记）

当任务是「把 N 页手写稿先转成文字」、整理留给父代理时，子代理只做 OCR 层，规则更窄：

- **一个子代理一个输出文件**（`tr_A.md`、`tr_B.md`…，放 agent 工作目录），绝不允许多个子代理追加同一文件（并发写会丢接、顺序不可复现）。
- **每页一个 `## p.NN` 标题**：父代理合并时按页号排序即可，无需记忆分片顺序；页号必须与文件名一致。
- **派活前先 `ls` 确认真实文件名**：`pdftoppm` 的补零位数取决于**总页数**（39 页 → `-01.png`，6 页 → `-1.png`），子代理按错误位数找图会报文件不存在。
- **禁止子代理“顺手修正”**：只转写、只标 `[?]`，不改公式、不补结论（修正留给父代理回图定案）；汇报里出现「我改了」的条目，父代理必须回原图复核。
- **子代理自报“已写 N 页”不算数**：父代理要 `ls -l` 核文件存在 + 数 `## p.` 标题数 = 页数，再拼接入库。

## 习题课 ≠ 转写（用户明确要求：「把知识提取出来，而不是单纯转写」）

习题课转写稿是按题号排列的习题流水；产出必须是**知识条目**。写成单独一份 `习题课整理规范.md` 给子代理读，要点：

- **删**：题号（`1.` `Exo 3` `第 16 题`）、题目措辞（「设…求证…」）、具体题目的凑题数值、小测/作业/考试字样。
- **留**：概念与结论、证明的关键思路（紧凑完整，不是抄题解）、有价值例子与反例、方法性总结。
- **判据**（用户原话）：这个结论**换个题目还成立吗**？成立 ⇒ 知识；不成立 ⇒ 题解痕迹。
- **按主题分篇**（不用「第 N 次习题课」当篇名）；页内条目用「定义 1.1 / 命题 1.2 / 例 1.3」**按本篇重排**。
- 与正课重复的定义**不重抄**，`[[链接]]` 过去；习题课独有内容（范畴论、自由群、辫群、诺特环、局部化、对称多项式、模与张量积）完整整理。
- 按内容（而非页码）归属：一页里跨两个主题、或某主题只在几行里出现，要顺手归到主题所在篇。

## 收尾：存疑点由父代理自己查清（2026-10-03 用户明确）

用户原话：「存疑的部分你自己先仔细核对，我再去看太麻烦。你改到言之有物且逻辑通顺语法正确就行。」
——**交付的笔记里不要留一堆 `[?]` 和待核清单让用户去看**，父代理要自己逐条定案。

- **定点精读的首选手法**：按需重转该页 `pdftoppm -r 300 -png -f N -l N in.pdf out`，然后用 `vision_analyze` 的 `region=[x1,y1,x2,y2]` 参数——**region 在降采样前裁剪、保留全分辨率**，比整页提问清楚得多，也比先 `magick` 裁图再问省一步。裁 ~1000x500 的区域最舒服；整页横排（页宽>页高）的档先 `magick -rotate 90` 转正再定位。
- **三类处置**：转写错 → 直接改；原稿笔误/自相矛盾 → 按数学改成正确表述（用户已授权）；无原稿依据的注记 → 删掉，或补上真正依据（例：Eisenstein 判别法补「$p$ 必须是素数，证明用到 $\mathbb{Z}/p\mathbb{Z}$ 是整环」）。
- **改写要写进 `log.md`**（改了哪几处、依据是什么），而不是把清单交回用户。
- **存疑点多时再派一轮「对照原图逐篇复校」子代理**：整理完的笔记里 `[?]` 一多，父代理逐条看图很贵；按篇分片（每片 6–12 篇）再派一批（可用完的并行槽）做第一遍定案——context 里**点明已知的存疑点/可疑页号**（否则子代理会重新发现一遍且可能给出不同读法），并要求「转写错→改；原稿笔误/矛盾→按数学改正；确实判不了→保留原稿字面并单列」、不允许残留 `[?]`。父代理再对报告里「我改了公式」的条目回图抽验——子代理的汇报是自述，不是已核实的事实。

## 跨课程同名概念页：用带路径链接消歧

同一概念在两门课各有一页（如 `群`/`商群`/`正规子群`/`同构定理`/`导群`/`群作用`/`模` 在代数 I 与代数 III）时，`[[群]]` 这类短链接在 Obsidian 里解析到哪个是不确定的。用户选定「**链接改成带路径的**」——统一写成 `[[代数I/概念/群]]`（Obsidian 显示 basename，不必加别名）。
批量做法：脚本按文件所属课程目录（`数学/<学科>/<课程>/…` 取第 3 段）给指向这些 basename 的链接加 `课程/概念/` 前缀；学科级 `_索引.md` 要**按课程段落分别加前缀**（不能整文件一刀切）；`[[00-总览]]`、`[[_索引]]` 等同名约定文件本来就该写全路径。改完全库复查「指向歧义 basename 的裸链接数 = 0」与断链 = 0。

**同名冲突是追溯性的**：新增第 N 门课会让第 1..N−1 门课里**原本不歧义的裸链接突然变歧义**（实测：新增代数 II 带来 `对称群`/`符号差`/`行列式`/`轮换` 4 个新名，波及旧课程 33 个文件）。因此新课程入库的收尾必须对**全 vault**（不只新课程）重跑 basename 重名扫描，并把旧课程文件与索引一起改——只改新课程会留下一批以后随机解析的链接。先跑一遍「全库 basename 出现次数 > 1 且含新课程」的对照表，再决定每个名在各课程里该指向谁（旧课程里没有该页的名，指向真正含此概念的那门课）。

## 结构约定的全库回溯：互链的两向生成

新增链接段、改段名、统一文件/标题格式这类结构约定，**都要对全库既有课程回溯执行**，不只改本次新建的课——否则新旧不一致，用户会要求「过去的文件也要检查」而返工。

1. **先全库摸底再动手**：递归 walk 每个含 `笔记/`、`概念/` 的目录，统计「笔记有篇末链接段 / 总」与「概念页有回链 / 总」。**课程目录嵌套不一**（如 `分析III/{Fourier,点集拓扑}` 各自带 `笔记/概念`），不能假设固定层级 `<课程>/笔记`。
2. **笔记 → 概念（要模型判断，派子代理）**：按课程分片补篇末 `## 相关概念`；只链真实存在的概念页，条数随该篇实际内容（3 条也合法）；跨课程同名用带路径链接。
3. **概念 → 笔记（用逆映射，别派子代理）**：笔记篇末段已把「笔记→概念」写全，把这批链接**反向聚合**就得到每个概念页的出处笔记——零额外模型调用，且与笔记内容严格一致。要点：
   - 解析链接时按来源笔记所属课程定目标：裸 `[[X]]` → 本课程的概念页 `X`；`[[课程/概念/X]]` → 那门课的概念页。
   - 给每个概念页加一节列出引用它的笔记，链接写**完整路径**（`[[课程/笔记/…/NN-篇名]]`），避免跨课程同名篇名冲突。
   - 绝大多数概念页都能映射到出处；剩下的少数（笔记里根本没链到的）再单独判断是链接漏了、还是该页应合并/删除。
   - **必须等第 2 步做完再跑**：笔记侧链接不全，逆映射就会缺出处。
4. 两向补齐后统一断链扫描 → 追加 `log.md` → `git add/commit/push`（`_索引.md`、`log.md` 由父代理统一改）。
