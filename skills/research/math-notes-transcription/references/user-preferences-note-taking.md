# 用户在笔记整理上的偏好（务必遵守）

## 用户偏好(务必遵守)

- **存疑处一旦定案(修好、或确认原稿就如此)就要顺手删掉该处的行内 `[?]`**(用户 2026-10-03:「修改好的地方标注的问号什么的每次都记得清理」)。没定案的保留;定案了还留着就是脏标记。批量清理要逐处回原图,改一处清一处(分析I 曾积下 18 处,清单在 skill coaching-index)。
- **复校时子代理会把用户已确认的更正改回错误值(2026-10-03 实测,重要)**:用户口头给出的更正(如「末例分子是 $n(n+1)$」「结论是小 $o$」)若不写进文件,下一轮复校的子代理会按自己的识读**把它覆盖回错值**。对策:父代理把用户每一条口头确认**单独记下来**,复校回来后**逐一回查**;必要时当场回原图二次确认(本例父代理回图看到 $\frac{n(n+1)}{1+n^2}$ 确实自洽)。
- **同一缩写会被反复误读**:`Démo`(证明)先后被读成 `Solovo`、`Snm`(同一页两处);`Lem` 被读成 `Semi`。转写这几个法语标记时**默认按 `Démo`/`Lem`/`Rq`/`Prop` 套**,字形不合再回图。
- **不要在手写笔记里留“整理者旁注”**:如「（原稿此处有涂改，未能辨读）」「（原文写作 X，应理解为 Y）」——用户要求笔记干净,一律压成行内 `[?]` 或删掉,分析写进交付报告。不确定就用原稿字面 + `[?]`,不替作者改。:课程笔记要干净——笔记内**只用行内 `[?]`** 标不可辨处,整理者的分析与疑问写在**交付报告**里,不要塞进笔记正文。(概念页的 `> [!warning] 陷阱` 不在此列,那是规范内容。)
- **语义优先于字形(2026-10-03 教训,用户强调)**:手写体的简写标记极易形近误读——实测把引理标记 **Lem** 读成 **Semi**、证明标记 **Démo** 读成 **Solovo**、**Rq**(Remarque) 读成 **Rg**、结论文里的 **推出** 读成 **排序**。判读规则:先问「这个词在这句话里讲得通吗」,再结合上下文(引理/定理/证明/注记)与原图字迹共同定,不要按字形硬认;拿不准就标 `[?]` 并报给用户。

- **用户禁止为文件编辑创建临时验证脚本**(2026-09 明确、反复强调,原话"写好了搞什么验证脚本,你当我眼瞎不会看吗"):不要为验证 wiki/笔记改动向 `C:\Users\...\Temp` 写 `hermes-verify-*.ps1`;改用内联单条命令、`search_files` 静态复查或直接读回文件。若工具链自动化仍要求 Temp 脚本证据,说明"用户明确禁止,已用内联验证代替",不要重复创建。
- **文件里禁止 emoji/装饰符号**(★⚠️✅ 等),用纯文字("注意"/"严格"/"不严格")
- **转写公式前先想“Obsidian 能不能渲染”(2026-10-03 用户提出)**：Obsidian 内置 MathJax 不认一些 LaTeX 宏，写进去就是一个红字/乱码：`\sh`（应用 `\sinh`）、`\cancel`（需扩展，别用；被划掉的内容要么略去要么改写）、`\textsuperscript`（用 `^e`）、`\xlongequal`（用户 LaTeX 宏里的自定义命令，MathJax 不认）等。写完用脚本扫一遍不支持的宏（如 `\\sh(?![a-zA-Z])`），别等用户在 Obsidian 里看到红字。
- **证明结束符是井号，不是 ♯**：用户写证明结尾用 `#`（刷稿里的交叉线拉长像 sharp），**绝不要转成 `\sharp`**；正确写法 `$\#$`。扫描时注意 `\sharp` 与 `\sh` 容易被漏。
- **例题归属按内容主题定，不按页码机械切（2026-10-03）**：扫描页带的重叠（一页里包含两章边界的内容）很容易把例子放进错的那篇——实测把三个属于“渐近分析”的展开例（$\sqrt{x^3/(x-1)}$、$e^{x\ln x}$、$I_n$）误归入了“级数”篇。拆章时逐例检查它所依赖的工具（导数展开？级数判别法？）到底属于哪一章。:不加入页码标题、转写说明、整理者中文说明或导航语句；原笔记中的示意图**用文字复述其几何内容**(或自绘 SVG),不要裁原图嵌入、也不要留 `[Diagram: ...]` 文字占位符。
- **整体格式统一**:用户提出行末标点、标题标点或其他格式要求时，视为对当前课程笔记既有内容和今后整理的全局规则；先整体扫描并一次性处理，不只修改新增部分。对于 `Prop`、`Déf`、`Rem`、`Thm` 等领起文本块的标签，统一采用同一种标点风格。
- **标点按正常书写习惯，不做逐行机械加标点**:句子在真正结束处才用句号；公式前用冒号领起（`tel que :`、`Donc :`）；跨行续句行内不加句号；显示公式内部句号放公式末尾；`!`/`?`/`;`/`:` 前按法语留空格；避免 `.).`、`Donc.`、`et.` 这类伪句号；YAML frontmatter、作者行、callout 标题不加句号；`\left`/`\right` 内容不要经 patch 工具转写（`\r` 会被吞成回车），改用 PowerShell 字符串替换。
- **孤立 display 块要合并成通顺段落**:OCR 常把一句拆成多个单独 `$$\text{...}$$`；应合并为一个 display 公式或转为正文句子，并顺手统一同段符号（如递推变量 m/n 混用取与命题一致者）。
- **合并/整理笔记时不要标注"出自讲义还是手写笔记"**(用户 2026-09 明确纠正):正文里不要带 `(讲义 Remark…)`、`(手写 p3)`、"(handout §…)"这类来源出处标注,也不要在开头/结尾写"本笔记由讲义+手写笔记合成"、文末 `## 来源` 小节——**只整理知识本身**。frontmatter 的 `sources:` 字段用来溯源文件名即可,正文干净。
  - **范围限定(2026-10 实测)**：这条针对**概念页**与**手写笔记/讲义合并**的正课笔记。习题课系列笔记反过来**要保留讲义编号括注**（`> [!note] 定义 4.1（Borel 子群，讲义 1.1）`，篇内编号续本系列），且 frontmatter 常常**不带** `sources:`。判据：**与该系列现有篇一致 > 本文的通用表述**——别把系列里的括注当脏标注删掉，也别给系列的篇硬加 `sources:`。
