# 笔记/概念页的内容纯度与格式规则（用户逐次明确）

这些是对 vault 内容的全局规则，与具体转写步骤无关，按需读。

### 概念页拆分原则(用户原话:"不要把所有概念放在一个讲义里面")

- **每个概念一个小文件**,不建大讲义文件
- 文件名:英文小写连字符(`group.md`、`normal-subgroup.md`),中文名放 frontmatter title
- **用户已明确偏好概念页标题和文件名优先使用中文或法语**；涉及跨课程格式统一时，扫描所有相关概念目录，整体重命名并同步所有索引和 wikilink，不只修改当前课程
- 每页结构:frontmatter + 定义(`> [!note]`)+ 直觉(`> [!tip]`)+ 例子(`> [!example]`)+ 陷阱(`> [!warning]`)+ 学习提示 + 相关概念(互链)

### 课程笔记的内容纯度与全局格式

- **笔记篇末必须有 `## 相关概念` 段**（照代数 I 既有约定，其 66 篇笔记全部有）：列出该篇实际讲解的概念页链接（按重要性排序，一般 4–8 条；该篇内容确实少就少写，不硬凑）。跨课程同名的概念页在链接里必须写带路径形式。此段是**「笔记不夹带导航句」禁令的既定例外**，不要因为纯度规则把它删掉。
- **互链是双向的，且结构性约定要全库回溯**：概念页除了「相关概念」（概念→概念）还要有回指**出处笔记**的一节（`## 相关笔记`，段名随课程语言）。只做笔记→概念会让概念页在 Obsidian 里没有 backlinks、看着孤立。**凡这类结构性约定（新增链接段、改段名、统一标题/文件名格式），一律对全库既有课程一并执行，不只改本次新建的东西**——用户会明确要求「过去的文件也要检查」；流程是先全库摸底（哪些笔记缺段、哪些概念页没有回链）再分批补齐，存量与新件标准一致。**整理新课时就把这两向链接要求写进给子代理的规范文件**，漏掉必然在交付后返工补做。
- **概念之间的链接要跨课程/跨学科，不只在同一课程内**（2026-10-03 用户明确：「不同学科之间相关的概念也应该有链接」，举例：物理的伽利略时空 ↔ 代数的仿射空间）。子代理默认只做**本课程内**互链，跨课程是空白——收尾必须单独跑一轮：给概念页的「相关概念」段补指向**其它课程/学科**概念页的链接。判据：同名/近义概念、上下位、工具与应用关系（实测高价值连接：物理「最小作用量原理」↔ 分析「最速降线与Euler-Lagrange方程」/「变分」；物理「伽利略群」↔ 代数 II「正交群」/「等距变换」/「半直积」；物理「仿射空间」↔ 代数 II「参照系」/「卡氏方程」；概率 `inegalites-lp` ↔ 分析 I「Hölder不等式」/「Minkowski不等式」；概率 `fonction-caracteristique` / `theoreme-central-limite` ↔ Fourier「傅里叶变换」/「Plancherel定理」；Fourier「L²理论与Hilbert空间」↔ 代数 II「数量积」/「正交族」/「谱定理」；概率 `tribu` ↔ 点集拓扑「拓扑空间」；`coefficient-binomial` ↔ 代数 I「二项式定理」）。做法：按课程分片派子代理（每片只改自己那批页、不改目标页，避免并发写冲突），context 里给**全库概念页清单命令**（`find /mnt/e/notes -path '*/概念/*.md'` 加**物理/理论力学/**——它的概念页是平铺的、无 `概念/` 子目录，别漏扫）与「跨课程同名页写带路径」「只链**其它**课程/学科的页（本课程内互链已存在）」「不硬凑，每页 0–3 条」。实测一轮把全库跨课程链接从 88 条提到 617 条（361/558 页）。
  - **概念页的出处节用逆向映射生成，不必再派子代理**：遍历全库笔记的篇末概念段（`## 相关概念` / `## Voir aussi`），反查每个概念页被哪些笔记引用，即可批量写出概念页的 `## 相关笔记`（中文课程）/ `## Notes du cours`（法语课程）节，条目形如 `- [[篇名|课程 · 篇名]]`（basename 跨课程重名时改全路径）。零额外 API、与笔记端天然一致。**用 defaultdict 时注意：`if back[c]` 这类取值会为未命中的键建空 set，随后循环写入就会生成空节** —— 先列出真正有出处的键、或写前 `if not notes: continue`。少数「概念页比笔记段更细」的漏项（实测：分析 I 的 Cauchy 根值/d'Alembert/Gauss/Abel/Dirichlet 判别法、Riemann 重排定理、无穷乘积、Cauchy 乘积、常数变易法，代数 I 的对称多项式/高斯整环/多项式的赋值/幂零根）要在对应笔记的段里补一条链接，出处才会出现。
- **课程笔记文件只保留原笔记内容**：不得加入“课程笔记续”、页码标题、来源说明、转写说明、整理者中文解释、导航句或阶段性元信息。页码只用于内部排序和验证，不能写入最终笔记；解释、背景和学习提示另写入对应的“概念”页。
- 用户提出的格式调整（如行末标点、标签后的冒号）是对整个既有课程笔记和今后同类整理的全局规则：先整体扫描，再一次性统一，不只修改新增部分。
- `Prop`、`Déf`、`Rem`、`Thm`、`Corollaire` 等领起文本块的标签必须统一采用同一种标点风格；默认统一为标签末尾加冒号。
- **续篇笔记按前半样式结构化(2026-09 用户满意定案)**:把视觉块标签(`**Exemples**`、`**1. Étude du cas $N=2$**`、`**a)**` 等)转为 `###`/`####` 标题;核心定理/注记/提问套 `> [!note]`/`> [!info]`/`> [!question]`(callout 每行加 `>` 前缀);**含多行 `aligned`/`array` 的证明块不要塞进 callout**(改动面大、易破坏公式),保留正文即可;callout 只包单/双行陈述与单行 `$$`。结构层级尽量沿用原文已有 `#`/`##` 标题文字,只调级别,不新造章节编号。

- **标签→callout 类型映射(2026-09-10 实战定型,先读前半对齐再动手)**:续写讲义时**不要用 `**Prop :**` 粗体标签**,一律转 callout。映射(参照该课笔记前半的既有用法):`Définition`/`Déf` → `> [!note] Définition`;`Prop` → `> [!info] Prop`;`Thm` → `> [!note] Thm`(带副标题写 `> [!note] Thm (Sylow)`);`Corollaire`/`Lemme`/`Conséquence` → `> [!note] …`;`Rem`/`Remarque`/`Notation`/`Interprétation` → `> [!info] …`;`Exemple` → `> [!example] Exemple`。**`Preuve` 不进 callout**,写正文粗体 `**Preuve :**`(与前文一致);`Conclusion` 同理用 `**Conclusion :**`。块内多段落/callout 内空行用单独的 `>` 行;块内列表/公式每行都要带 `>` 前缀。
  - **收尾必查(机械一致性)**:改完扫三项——① `^\*\*(Déf|Prop|Thm|Corollaire|Lemme|Rem|Exemple|Notation)` 在续篇区应为 0;② 裸 `^Preuve :`(不带粗体星号)应为 0,统一成 `\*\*Preuve :\*\*`;③ `^> \[!` 计数应约等于块数。注意**前半本身是混用的**(部分块用 callout、部分用 `**Déf :**` 正文),所以判断标准是"续篇区内部统一 + 与该课最显眼的既有 callout 风格一致",不必回头改造前半——**除非用户随后要求统一全篇**。2026-09-10 实际发生:先只让改续篇,做完后用户说"前半格式也可以顺便改了"。**默认预期就是全篇一致**(用户此前已定调:格式要求是对既有内容的**全局**规则),所以做局部重排时就把映射表/扫描命令留成可复用的,别写成一次性。

- **跨 30+ 块的机械格式转换:写一次性转换脚本,不要逐块 patch(2026-09-10 实战,34 块)**:逐块手改要几十次工具调用且必漏。步骤:① 用 `write_file` 在纯 ASCII 路径(`~\Downloads\`)生成 `_fmt_*.js`——用 **Node 而不是 PowerShell**,免受 GBK 无 BOM 解码与 `$PSScriptRoot` 异常影响;② 脚本内用**绝对路径**读写目标 md,逐行匹配 `^\*\*(.+?)\s*:\*\*\s*(.*)$`,命中映射表就把标签行换成 `> [!type] Label`、其后**连续非空行**逐行加 `> ` 前缀,遇空行或边界(如 `## Références`)停;③ 硬编码排除清单(`Preuve*`/`Conclusion`/分情况枚举 `**Si … :**`)不转;④ 跑完**回读抽查**(挑一个含多行 `aligned` 的块确认 `>` 前缀没破坏公式)+ `git diff --stat` 看规模 + 正则扫残留标签行;⑤ 删掉临时脚本。
  - **关键区分:转换脚本 ≠ 验证脚本**。用户禁止的是 `hermes-verify-*.ps1` 这类**为核验改动**而建的脚本;为完成**大量机械编辑**而写、跑完即删的一次性转换脚本是正当工具。**别把禁令扩大化到手写 34 次 patch 的地步。** 若运行时反复弹出"请建验证脚本"的提示(本会话连弹两次),照旧拒绝并改用内联核验,说明理由即可;顺手清掉 Temp 里遗留的 `hermes-verify-*` 旧文件算加分。

- **原笔记的"缩写"与"箭头旁注"要展开并按正常顺序并入正文(2026-09-11 用户明确要求)**:手写法语讲义里常有
  ① 缩写标签(`Thm.`/`Prop.`/`Rem.`/`Rq.`/`Rapp.`/`Déf.`/`p.p.c.m.`)、缩写群记号(`G_n` 实为 $\mathfrak{S}_n$、`A_n` 实为 $\mathfrak{A}_n$);
  ② 用**箭头或括号补在下方/旁边**的对前文的补充说明(如把 $\sigma'$ 的定义补全、给 $C(u)$ 的推理加一个旁注分支)。
  用户要的是**成品笔记,不是忠实影印**:缩写一律写全(`G_n`→`\mathfrak{S}_n`),箭头旁注**按行文顺序直接并进对应段落**,
  不要保留"旁注/补充"这种形式,也不要另起一段放"另注"。本次据此重排了三处($C(u)=G$ 的分支、$\sigma'$ 的补全定义、5-循环类分裂的说明)。
- **不要因为"手写稿只写了半句"就照抄半句**:箭头旁注往往是作者自己意识到前文不严谨而补的条件。**转写时把它补进正文后,
  要检查补进去之后推理链是否闭合**——本次顺着旁注补全 $C(u)$ 那段,才发现必须显式用到"$4 \mid |C(u)|$ 且 $6 \leqslant |C(u)| \leqslant 10 \Rightarrow |C(u)|=8$ 而 $8 \nmid 60$"这条链,原稿只给了半截。
- **改造原文时不要静默改动**:展缩写、并旁注都属于"按用户指示的整理",但若因此改变了数学内容(补出了原稿没写的中间步骤),
  在 `log.md` 里记一句"按指示展开/补全"并列出补了什么,便于日后回看时区分"原文如此"与"整理者补充"。

### 作业/练习材料的处理:不单独成章(用户 2026-10 明确)

整理某门课的**作业/练习**(或习题课讲义里的作业部分)时:

- **不要留整节「作业与练习」**。只保留**与讲义正文有对应节点**的题,且必须**作为例题/练习内嵌进对应小节**(`> [!example]` / `> [!exercise]`);与正文无对应节点的题(纯考试题、后续内容)**直接不收录**。
- **去掉作业编号与出处字样**——「第 X 题」「出现在第 X 次作业中」一律不写。判据与概念页一致:这题换个语境还成立吗?
- 用户原话:「作业与练习不需要保留, 除非是和讲义内容强相关的, 可以作为例题或练习放在正文中, 不要留一章单独的作业题」。
- 同一规则也管**概念页**(详见 `wiki-writing-conventions` 的「概念页 ≠ 题解汇编」及其 §4g)。
- **收尾扫描**:对概念页/笔记跑禁用词 `作业|hw[0-9]|第\s*[0-9]+\s*题`(概念页应 0 命中;笔记里只出现在 frontmatter `sources:` 属正常)。

### 并入既有课程笔记系列(新讲义 → 已有 `NN-篇名` 序列)

目标课程已有成套笔记时，本次是**续写系列**，不是新建体系：

- **动手前读该系列最近 2–3 篇**，照抄这几样：frontmatter 字段集（`title/created/updated/type/tags/confidence`，必要时加 `sources`）、H1（`# N 主题（日期）`）、小节编号 `N.1`、callout 标签样式、篇末 `## 相关概念`。新篇接既有最大编号，并同步该套 `00-总览.md`。
- **冲突时以既有文件为准**：通用偏好条目（如「正文不写出处标注」）与该课程既有笔记的实际形态冲突时，跟既有文件走。代数 III 正课/习题课笔记把原讲义编号写进 callout 标题括号（`命题 7.3（两个定义的等价，讲义 1.1）`），这是该系列的既定风格；`sources:` 仍只写讲义名，不写文件名或路径。
- **「删题号」有适用边界**：来源是**学生手写习题课流水**（问题接问题）时按知识条目提炼；来源是**助教印发的编号讲义**（`1.1`、`1.3.5` 这类编号，常含判断题与往年考题）时保留题面与编号——它们就是该系列笔记的正文组织单位。判据是来源形态，不是「习题课」这个标签。
- **归属判定**：无名 PDF 属于哪门课/哪套讲义，看它内部编号能否与既有笔记引用的「讲义 X.Y」对齐，比看文件名可靠。
- **讲义 PDF 归档**：按 `user-math-library` 的目录规则（课程材料进 `/mnt/e/书籍/<学科>/<课程>/习题课讲义/`，命名沿用下载名或该目录既有风格），**移动而非复制**，移动前后各跑一次 `md5sum` 核对，归档后清空 `~/下载`。
- **交付顺序**：候选稿先写 `~/.hermes/cache/scratch/`（不在 vault 里原地长），跑确定性检查（`wiki-writing-conventions` 的 `check_wikilinks.py` + `lint_natural_chinese.py`）→ 派**无上下文子代理**评审数学正确性/忠实度/交换图箭头方向 → `write_file` 落盘 → 更新 `00-总览.md` 与 `log.md` → `git add/commit/push`。新建笔记多半超过 4 KB，正好触发 `wiki-writing-conventions` 的**大编辑门槛**，按它走完整流程。

### 句末标点与标签:按正常语言习惯(用户 2026-09 收回「每行加句号」)

- 用户曾说「行末没有标点看起来很奇怪」,随后明确收回:原话「句号逗号只是我随口一说,你按正常语言习惯来就好」。**不要为追求每行都有句号而脚本化逐行补齐**——机械补齐会产生 `Alors.`、`donc.`、`tel que.`、`et.` 这类伪句号(句子根本没结束),用户逐条打回,浪费时间。
- 正常语言习惯:句子真正结束才用句号;跨行续句(行首小写接前句)的行尾不加句号;领起显示公式的行尾用冒号(`tel que :`、`Donc :`)或无标点(`L'application` + 公式 + `est bijective.`);法文标点前留空格(` ; `、` ! `、` : `)。

- 领起文本块的粗体标签(`Prop`/`Déf`/`Rem`/`Thm`/`Preuve`/`Corollaire`/`Conclusion`/`Motivation`/`Question`/`Exercice`/`Application`)统一 `**X :**`,修掉 `**X**:` 与 `**X :** :` 双冒号;`$\underline{\text{Thm}}$` 类下划线标签也转 `**Thm :**`;frontmatter/作者行/callout 标题(`> [!info] Rem`)不加句号。
- 机械句号的残留症状与定点修复:伪句号如 `Donc.`(领公式)→ `Donc :` 或去点;`tel que.` → `tel que :`;`(…$).` 括号外多余句点 → `(…)`;双句号 `Cayley..` → 定点 replace 为单句号。**禁止全局 `..`→`.` 正则替换**(会破坏 `\ldots`、`1,..,m` 等 LaTeX 序列)。
- **排查"诡异换行"先分清渲染真相**:markdown 单换行在 Obsidian 渲染为同一段落内的空格,跨行续句(行尾逗号/无标点+下行小写开头)视觉正常,**不用合并**;真正诡异的是 OCR 把一句拆成多个独立 `$$\text{...}$$` 块、`\left.`/`\right.` 跨行拼出的残缺公式、或一行一个短 `$...$` 碎片——这些才要合并/重排。快速定位断裂散文行的一条扫描(Windows PowerShell):
  ```powershell
  $lines=[IO.File]::ReadAllText($f) -split "`r?`n"
  for($i=0;$i -lt $lines.Count-1;$i++){ $t=$lines[$i].TrimEnd(); $n=$lines[$i+1].Trim()
    if($n -eq '' -or $n -match '^(---|#|\$\$|>|!\[|•|\*|[0-9]\.|\\|\()'){continue}
    if($t -match '^(---|#|\$\$|>|!\[|•|\\begin|\\end)'){continue}
    if($n -match '^[a-zà-ÿ]' -and $t -notmatch '[.!?:;]$'){ "{0}: {1}" -f ($i+1),$t } }
  ```
  输出候选后逐条目检(frontmatter、交换图 `@V...VV`、aligned 行属正常误报)。

### 笔记中的图片与示意图

- **插图规则(2026-10-03 用户明确)**:不要嵌用户手绘/扫描图的裁片;需要图示时优先**文字描述**,其次**自绘 SVG**。若沿用旧的 `![[附件/文件名.png]]` 写法请先确认是你自绘的图。
- 原笔记有示意图但用户要求重绘时，依据原图和用户明确几何要求绘制实际 SVG，而不是写 `[Diagram: ...]` 占位文字或插入原页截图。绘图前确认对象、可见/遮挡关系和标注；三维球面示意应使用球面轮廓、纬线、斜向贯穿直线、中心和端点标注，隐藏部分使用虚线；“直径所在的直线”应画成延伸到球面外的 `<line>`，而不是只画球内线段。
- **三维球面示意图的几何细节(2026-09 用户逐轮打回后定型)**:
  - 球用**正圆**(`<circle r>`),不要用扁椭圆当球体——扁的视觉是椭球。
  - 斜直径是**整条直线**(延伸到球面外两侧),用 4 段 `<line>` 拼:球外两段实线、球内两段(端点到球心、球心到另一端)虚线 `stroke-dasharray="10 8"`。虚线是"被球体挡住的部分",方向不可画反。
  - `p`、`-p` 必须精确落在球面上(端点到圆心距离 = 半径),标签文字要远离直线放置(文字与直线间距留足,避免线穿过字母)。
  - 纬线画成与球轮廓**相切**的椭圆弧:`rx` 取球半径,左右端点落在球轮廓上(两曲线共切竖直线);后半(上方)虚线、前半(下方)实线;用弧命令 `M左,cy A rx,ry 0 0 1 右,cy` 与 `sweep=0` 下半。
  - 手写坐标前先心算验证:端点在线上、端点在圆上(勾股),标签不与线相交。
