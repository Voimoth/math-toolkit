# 讲义推进摄入（同一门课的讲义出新版本）

### 讲义推进摄入(同一门课的讲义出新版本)

适用：用户传来某门课**更新/更长的讲义 PDF**（如 `sofar (1).pdf` 从 17 页变 36 页、`代数III.pdf` 接续前一份），要求"更新笔记和概念"。**这不是新主题摄入，而是"课程进度推进"**。

0. **先查有没有并行/遗留会话已经做完这件事(2026-09-10 教训,差点整份重做)**:开工前 `git log --oneline -5` + `git status --short`。本会话准备"更新代数III笔记和概念"时,发现这活已被另一条工作线提交完(commit 已推送、`log.md` 条目都写好了)。**发现已完成时不要重写,转为质量核验**——这个核验正是随后查出 `n≠4` 被误改成 `n≥5` 的入口(见上文"原文自相矛盾"那一条)。核验顺序:回读目标文件 → 抽查与原始材料(讲义提取文本/原图)的对应关系 → 扫残留与断链;发现误改就按"改原文前必须回原图确认"的流程定点修回,并把误改正过程的叙述同步改进 `log.md`(别留着"修正原文矛盾"这种已被推翻的说法)。
   - **续篇可能是「续篇的续篇」——先定位接续点再动手(2026-09-11)**:同一门课用户已陆续给了 3 份材料(`Cours USTC 01-09-26.pdf` → `代数III.pdf` → `扫描全能王 …`),每份都是接着上一份的。**读新扫描件前先读现有笔记的末段,确认它结束在哪一节**,再判断新材料的起点是否正好衔接(本次新材料起于「Conséquence : l'ordre d'une permutation…」,正是笔记最后一条 `Conséquence` 块的下一行)。**若起点与笔记末尾有重叠或跳接,先弄清是要「补充」还是「接续」**,不要默认从文件头平行追加。frontmatter 的 `sources:` 应逐份累加(本次加到第 3 条)、`updated` bump 到当天。

1. **先摸清增量再动手**：提取新讲义，与 `笔记/` 下已归档的旧提取文本对比（或读旧笔记末尾），确定新增了哪些章/节。不要重写已覆盖内容。
2. **进度驱动的概念页决策**：
   - 新节有实质内容 → **新建概念页**（按内容切分，不建大页）；
   - 新节回答/更新了旧页表述 → **回头修掉旧页的过期句**。典型过期句："此内容属后续章节，**当前不在范围内**"、"第 X-Y 章尚未覆盖"、"待课程推进再补"——课程推进后必须改，并删掉 `_索引.md` 里对应的"暂缺/待填充"注记；
   - 旧页被新讲义正式覆盖 → 从 git 历史取回重建，按新讲义重写（见"陷阱"节的"旧页重建"）。
3. **笔记续写**：接在原有笔记末尾**同一文件内**，frontmatter 加第二个 `sources:` 条目并 bump `updated`；**保持前半的样式**（标签冒号风格、callout 层级、`###` 编号），不另起炉灶。
4. **索引与进度**：更新该课 `_索引.md` 的当前进度、学科 `_索引.md` 的进度行、根 `log.md`；若讲义**目录**列了尚未讲授的章节，明确标注"目录已列出但正文未讲授，故暂不建页"（不要把目录当内容）。
5. 断链/emoji/双重转义检查 → git add（只加目标文件）+ commit + **推送**。

- **判"学到哪"看正文结尾,不看目录(2026-10 实战)**:讲义开头的目录常是**整门课的总目录**(列到尚未讲授的章节,页码可到 100+),而文件本身可能只有几十页(如名为 `sofar` 的进度版)。以**正文最后一条**为准(常带「X 月 X 日的课结束在这里」或最后一个命题/注),据此定建页边界,并在笔记与 `_索引.md` 里写明「目录已列但正文未讲授,故未建页」。
- **多章讲义 → 笔记 + 概念页的批量整理可派子代理,但必须自己复核**:派活时在 context 里给全写作规范(禁 emoji、`$...$`/`$$...$$` 分隔符、概念页只写概念且不附习题串/不写作业出处、`[[wikilink]]` 只指现存页、目标文件绝对路径、**只追加不改旧文**)。子代理的完成报告是**自报、不算证据**:回来后自己 ①`git diff --numstat` 确认是「只追加」而非改写;②跑内联断链/emoji/坏转义检查(先建现存页 basename 集合比对);③抽查 1–2 个新页;④对概念页/笔记跑**禁用词扫描**(`作业|hw[0-9]|第[0-9]+题` 应 0 命中)。全部通过再统一 commit + push。
  - **子代理会「看错原图」,而这件事在它的报告里完全看不出来(2026-10-03 实测)**:同一批里,子代理声称已回图核对,实际仍把 `Lem` 读成 `Semi`、减号读成加号、`Lyapunov 泛函` 读成 `Lagrange 恒等式`、并集读成交集。所以**抽查 1–2 页远远不够**:公式、人名、符号这三类**关键行必须自己逐处回原图核**——优先核子代理标了 `[?]` 的行、它自称"已回图核对"的行、以及所有定理/命题陈述行。
  - **子代理不会读中文句子**:「纯手算」被转写成「落手算」这类**形近/音近误读**,数学核对完全抓不到。所以复校要**单列一轮「只读中文、不看公式」**的通读,把它当成一道独立工序,别指望数学校对顺带发现。
  - **子代理会把读不出的字当事实写出来**:疑似人名/术语的乱码(如 "Jrddlam / Notker Tilbent")不要照抄成事实,一律 `[?]`。用户往往认得原文,问一次就能得到正确写法(本次为 `(Fredholm 二择一, Hilbert)`),而且**他给的写法还要自己验一遍是否确有其人或定理**。
  - **并发子代理必须按「页范围」分工,且先把分章源文件切好**:同一目录被多个子代理同时写时,**章与章相邻的边界页**(如 p43/p44/p48/p53/p61/p64)会被两方各自整理一遍、内容打架。派活前先按内容把整份转写切成 `NN-章名.md` 一类小文件,每个子代理只负责明确的几篇 + 明确页码区间;边界页要在派活时点名归谁。

- **旧页重建(2026-09-10 实战,处理"过期删除"的正确姿势)**:若之前因"讲义未覆盖"删过概念页、现在课程推进需要它,**从 git 历史取回而不是凭记忆重写**:
  ```bash
  git log --oneline --all --diff-filter=D -- "数学/.../概念/<topic>.md"   # 找删除它的 commit
  git show "03f1366^:数学/.../概念/<topic>.md"                          # 取删除前的内容
  ```
  取回后**必须按新讲义重写并改掉旧版的硬伤**——旧版是在更少材料下写的,常含过度断言。实例:旧 `fejer-kernel.md` 把 Fejér 定理条件写成"只需连续"(漏了周期性/$2\pi$ 周期),并断言"法国体系先证 Fejér、体现先易后难";而讲义实际是**第 3 章先上 Dirichlet 核与 Dini,第 4 章才讲 Fejér**。**不要因为旧页"曾经存在"就照抄它的结论**——旧页可能正是当初被删的原因之一。重建后同步:文件名/标题改中文(用户偏好)、`_索引.md` 补条目、旧文件名不再被任何 `[[wikilink]]` 或 frontmatter `sources:` 引用。

- **vault 膨胀可能根本不在工作区里——`.git` 才是**(2026-09-11 实战,157.8 MB 死重)：用户说"notes 里好像有不少冗余文件"时，**别只扫工作区**。本次工作区只有 1 MB 笔记、`git status` 干净、`git log` 正常，而 `.git` 有 159 MB。诊断链（`git count-objects -vH` → `git verify-pack -v` 列大对象 → `git fsck --unreachable --dangling` 判可达性 → 用当前文件 blob 交叉验证）+ 孤儿对象二进制安全导出 + 清理前的远程同步检查，全部写进 **`references/git-repo-bloat-and-lost-objects.md`**。两个最容易错的点：① 用 `rev-list | head -3000` + 逐对象 `cat-file -s` 查大小会**得出错误结论**（截断 + 静默失败），要直接用 `verify-pack`；② 几个 MB 的 JPEG/PNG 很可能是**用户的手机照片**，unreachable 对象删了就永久没了——**必须先导出到仓库外交用户目检，不要自行删除**。
- **同一类命令连续失败 3 次就停下换思路**:先怀疑编码/路径,换纯 ASCII 路径或换工具重来,不要在同一个假设下继续微调参数。
- **提交信息用 `-F` 传文件,不要 `-m` 内联**:多行中文 commit message 用 `git commit -m "第一行\n第二行"` 容易被 shell 的引号/换行解析搞坏。正确做法:先用 write_file 把 message 写进临时文件,再
  ```bash
  git commit -q -F /tmp/_commit.txt
  ```
  `git push` 后看 `xxx..yyy  main -> main` 那一行判定成功(git 把进度写 stderr)。

## 单份材料入库（用户丢来一份 PDF → 既有系列新增一篇）

适用：用户在 `~/下载` 放下一份讲义/习题课材料，说「整理到 <课程> 笔记里」。这既不是整门课的批量转写，也不是同一份讲义的续页，而是**给既有系列追加一篇**。

1. **先定位它是什么、属哪一套、是第几篇**：读材料正文找它**自带的编号体系**（如 §1.3、练习 1.3.5），再到既有笔记里 `grep -rn "讲义"` 看同系列篇引用的是什么编号（`（…，讲义 1.1）`）；编号体系对得上 ⇒ 它是同一份讲义的新章节，追加为该系列的下一编号 `NN-主题.md`。再看 `git log --oneline -8` 与该系列既有篇的 `created` / H1 里的日期，定新篇的编号与日期。正课与习题课各有独立编号序列，别混。
2. **归档材料 PDF**：`/mnt/e/书籍/<学科>/<课程>/习题课讲义/`（作业 → `作业/`、TD → `TD/`、手写 → `手写笔记/`），命名沿用下载名或该目录既有风格；`mv` 前后各算一次 md5 核对，收尾清空 `~/下载`。vault 里不放 PDF，`sources:` 只写讲义名称、正文不写路径。
3. **照该系列现有篇的写法，而不是照跨课程通用约定**（最易踩）：frontmatter **字段集照抄系列**（代数III 习题课 = title/created/updated/type/tags/confidence，**不加 `sources:`**）；callout 标签格式照抄（`> [!note] 定义 4.1（Borel 子群，讲义 1.1）`——篇内编号按本系列续，讲义原编号放括注）；H1 写成 `# N 主题（日期）`；篇内小节编号续本系列（7.1、7.2…）。已知冲突见 `references/user-preferences-note-taking.md` 里那条「不留出处标注」的范围限定。
4. **动笔前读 2 篇近邻篇**（同系列上一篇 + 同课程正课里讲同一主题的那篇，避免重抄正课已写的定义，重复处 `[[链接]]` 过去）与该套 `00-总览.md`。
5. **新篇超过 ~4 KB 就走大编辑门槛**：候选先在 vault 外写 → 跑链接/公式/自然度检查 → 派**无上下文子代理**评审。给评审者**原始 PDF 的提取文本路径**（否则它无法核忠实度），要求它开头引候选 sha256、按「错误 / 格式 / 表述」三类列发现并给判定。评审常抓到的两类：与系列 frontmatter/编号不一致；推导与证明留在 callout 内（应移出为正文 `**证明.**`）——照办。
6. **收尾**：更新该套 `00-总览.md`（篇目表 + `updated`）→ 若学科 `_索引.md` 列了篇目就同步 → `log.md` 追加一条（起因/内容/流程/顺手改了什么）→ `git add` 只加目标文件 → commit + push；篇里有 CD 交换图时加跑渲染色检（配方见 `wiki-writing-conventions/references/exchange-diagrams.md`）。
