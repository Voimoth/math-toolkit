# 手写扫描档的 Linux 全流程与校对纪律（2026-10-03 实测：54 页法文手写正课笔记）

用户给扫描档（如「扫描全能王」导出的手写笔记 PDF）并要求「整理进笔记」时按此流程；**重点是校对**，用户对此要求很硬。

## 1. 转图
```bash
pdftoppm -r 200 -png in.pdf p        # 54 页约 29 s、~106 MB；手写 200 dpi 足够
```
300 dpi 的体量参照（CamScanner 手写件）：117 页 ≈ 2 min / 335 MB，70 页 ≈ 84 s / 231 MB（约 2.8 MB/页）——转图前先 `df -h /home` 看空间。

## 2. 批量视觉转写
```bash
python3 <skill>/scripts/vision_transcribe_batch.py --dir <图目录> --start 1 --end 54 \
  --model deepseek-flash --prompt '<英文 prompt>'
```
- **Prompt 用英文**，写明：verbatim；LaTeX 用 `$...$`/`$$...$$`；不翻译、不总结、看不清写 `[?]`；keep the original French wording；**Output only the transcription, with no preamble**。
- **正文是中文手写、术语夹法语时**：把语言那句换成 `Keep Chinese text in Chinese and French terms in French exactly as written`，其余照旧（这句同时管住「别把中文翻成英文」和「法语术语原样保留」）。实测 182 页（113 正课 + 69 习题课）`ok=181 skip=1 fail=0`、约 5 s/页；两个进程并行约 10 分钟。
- **转图前先看原生分辨率**：`pdfimages -list -f 1 -l 2 in.pdf`。CamScanner 件通常 2200–3500 px 宽 ≈ 290–300 ppi —— **渲染 ppi 超过原生值只是插值**，300 dpi 已够；硬上 600 只会把图撑大到 3–4 MB/页、拖慢上传。
- 已有 `.txt` 自动跳过（断点续转）。实测 54 页 `ok=53 skip=1 fail=0`。
- **同时跑两份时别用 `( cmd & )` 包进一个 background 调用**：`( ... & )` 把子进程丢进 detached 子 shell，外层 shell 的 `wait` 无可等、立刻返回，**session 被标记 exited、完成通知不会来**，而两个 python 仍在跑（孤儿进程），只能自己轮询。两种可靠做法：① 每个任务单独一次 `terminal(background=true, notify=true)`；② 单个前台命令里 `while pgrep -f '<脚本名> --dir <目录>' >/dev/null; do sleep 15; done` 阻塞等待。
- **等待命令返回 ≠ 转写完成**：工具自身的等待上限可能先到（前台 timeout 会被截短）。等完先 `ls <图目录>/*.txt | wc -l` 核对页数，再往下走。
- **进度/速率别靠猜**：`ls -l --time-style='+%T' *.txt` 看相邻 `.txt` 的 mtime 差就是每页耗时。实测 deepseek-flash 转 300 dpi 手写件约 4–5 s/页（117 页单进程 ≈ 8–9 min）。

## 3. 机械修复（脚本批量，成稿前做）
- `\(`/`\)` → `$`（模型偶尔仍输出反斜杠定界符，Obsidian 不渲染）；
- 删整页被包进 ` ```markdown ` 的围栏（本次 p-30 整页）；
- 删页脚水印「扫描全能王 创建」——**按子串删（`t.replace('扫描全能王 创建','')`），不要整行删**：水印常黏在正文行尾或紧贴下一页首行（实测出现 `扫描全能王 创建Donc le résultat…` 这种黏连），整行删会连正文一起删掉；删完再压掉留下的空行。
- 清开场白（"Voici la transcription…"）；
- **删模型的整页元评论行**：视觉模型偶尔在页首输出 `The image has been rotated 90 degrees counterclockwise. Here is the recognized text:` / `OCR result` / `Here is the transcription…`。**看到这句不要以为该页需要旋转重转**——先看正文与邻页首尾是否衔接：本轮两页带此提示的正文完全正常，只是多了一行前言，按行正则删掉提示行、内容照用。
- **页码不是内容**：某页转写稿首行若只有一行包在 `$$ … $$` 里的页码（形如 Page 41），那是模型把印刷页码当成了正文。回原图确认该页正文是否完整——常见情况是标题与正文都在、只多这一行，删掉即可，**不要当成漏页去补写**。

## 4. 校对（不可省；用户明令「一定要仔细校对」）
逐处**回原图**核对可疑数学符号（`vision_analyze` 看 `p-NN.png`；看不清就裁剪放大后再问）。
**必须区分两种情况**：
- **转写错** → 直接改（如本次 p03 `q_2^{-1}`→`q_1^{-1}`、p12 正合列首项 `Z/pZ`→`Z/qZ`、p22 `Aut(Z/2Z)`→`Aut(Z/2Z×Z/2Z)`、p42 `dim ker u^k` 求和上下限）；
- **原稿本身笔误/无法辨认** → **保留原稿写法**，另列清单报告给用户请他核原笔记本（本次 6 类：`d|n` vs `d|q-1`、exposant 的 minimum/maximum、`G/H` 疑为 `G\H`、`E_{ij}(λ)` 疑漏上标 `^{-1}`、`D_i(λ)=λE_{ii}` 与旧定义矛盾、末页无证明）。**禁止把第二种当第一种静默改掉。**

## 5. 别误报漏页
「主题切换」不等于漏页。判据：**逐页核对「本页末行 ↔ 次页首行」是否连贯**，并确认末页有没有被裁切（看页面下缘是否完整）。本次 54 页全部首尾相接，无缺页——不要凭「衔接生硬」就报漏页。

## 6. 成稿
- 保留原文语言（法文）不改写；公式全用 `$...$`/`$$...$$`；
- 与课程笔记同款 callout：`> [!note] Déf./Prop./Thm.`、`> [!info] Rem.`、正文 `**Preuve :**`（长证明不进 callout）；
- 按内容补 `## 大节`/`### 小节` 标题；UTF-8 无 BOM，禁 emoji。

## 7. 接续与归档
追加到**同一课程笔记文件末尾**（`---` 分隔），frontmatter `sources` 累加这份 PDF 的原名、`updated` bump 到当天；原 PDF 归档到 `/mnt/e/书籍` 对应课程目录（位置见 `user-math-library`）。

## 法文手写数学的常见转写错（校对时重点盯）
- 下标近似：`q_1`↔`q_2`；
- 求和/整除符号：`d\mid n` vs `d\mid q-1`；`r\wedge s=1` 被读成 `r\mid s=1`；
- 模数层级：`\mathbb{Z}/p\mathbb{Z}` vs `\mathbb{Z}/p^\alpha\mathbb{Z}`；
- **p↔q 互换**（正合列首项、`Aut(Z/qZ)`、`Z/(q-1)Z`）；
- 漏乘号：`\mathrm{Aut}(\mathbb{Z}/2\mathbb{Z})` 应为 `\mathrm{Aut}(\mathbb{Z}/2\mathbb{Z}\times\mathbb{Z}/2\mathbb{Z})`；
- 漏上标 `^{-1}`、漏 `\mathcal{D}`、多插 `\mathcal{D}`；
- `\vee`(ppcm) 被读成 "PVQ"、`\wedge`(pgcd) 读成 `\mid`；
- 求和上下限、整页公式未 LaTeX 化（本次 p-52）。

## 按内容切分作业 PDF
本机无 `qpdf`/`pdftk`/`pypdf`，用 poppler：
```bash
pdfseparate in.pdf pg-%d.pdf            # 拆成单页
pdfunite pg-1.pdf pg-2.pdf pg-3.pdf out.pdf
```
同一页横跨两个主题时（本次习题 4.3 拓扑题与第四周 Fourier 题同页）**允许重叠页**：两个主题目录各含该页，并在报告里说明。

## 整份/整学年笔记入库：79 页 → 20 章 → 5 个子代理并行（2026-10-03 实战）

用户给的是**一整年**的手写课堂笔记扫描档（79 页，中文＋法语术语混排）时，上面的"接续"流程不够用——这次是**从零建整门课的笔记体系**，按下面走：

1. **转图用 300 dpi**：字小的档 200 dpi 会丢上下标与花体；`pdftoppm -r 300 -png in.pdf png/p`（79 页约 100 s、265 MB）。图与转写稿都放 agent 自己的 cache 目录，不进 vault。
2. **先合并、再切章**：全量转写完成后先做机械修复（去前言/水印/坏定界符/幻觉行号），然后**通读全稿**列出章节结构和页号边界，再按内容切成 `NN-章名.md` 小文件（本次 20 篇）。**不要**让子代理各自从整份大稿里找自己那段——页码重叠处必然打架。
3. **先把规范写成文件，再派子代理**：把写作规范（格式、frontmatter、callout 映射、概念页规则、`[?]` 纪律）落成 agent 工作区里的 `整理规范.md`，每个子代理的 context 只写「第一步 read_file 该规范 + 你的页范围/编号区间/主题」。**不要把整份规范复制进 N 份 context**——重复的规范既烧 token、又容易各自漂移。两套笔记（正课/习题课）各一份；习题课那份另加一节「提炼知识而非转写」：删题号与题目措辞、按主题分篇（不用「第 N 次习题课」当篇名）、页内重编号（定义 1.1/例 1.3）、重复正课已讲的定义不重抄只用 `[[链接]]` 带过。
4. **给每个子代理不重叠的编号区间 + 页范围**（如 `A: p001–007 → 编号 01–04`）：避免并发写同名文件、避免边界页重复收录。区间会留空号，由父代理收工核对。
5. **相邻段共用一页时**（边界页）在派活时报明**该页归谁**，只让一方收录。
6. **分批派以尊重并行上限**：一次 `delegate_task` 最多 10 个；两套笔记就分两批（本轮先 10 个正课、再 7 个习题课），不要一次派 17 个。
7. **派活前把子代理切到非思考路由**：长机械 fan-out（每个子代理几十轮工具调用）正是刷 `Go.` 的高发场景。子代理**继承父模型**、`delegate_task` 不能逐任务指定，只能改配置：`hermes config set delegation.model deepseek-chat` + `hermes config set delegation.provider deepseek`（`delegation` 段默认不存在，set 会新建）。机理见 skill `hermes-model-config`。
8. **同名概念页的冲突保护**：规范里写明「建页前先确认目标文件是否存在；若同批别的子代理刚写过，**跳过并在汇报里列出**，交父代理合并」。`write_file` 对「被 sibling 改过、自己又没读过」的现有文件会直接拒绝——照这条规则办，冲突只是少写一个页，不会丢内容。
9. **父代理收工必做复校（子代理的汇报是自述，不是已核实的事实）**：① 机械扫描 `xlongequal`/`cancel`/`\sh`/页标记 `=====`/emoji/残留粗体标签；② **断链检查**（注意 `$K[[X]]$` 这类数学记号会被误报成 wikilink，改写成 `K[\![X]\!]`，别新建页面）；③ 抽查回原图——**尤其复核子代理自称「我按标准改写了公式」的每一处**（本轮有一处子代理以为在纠错、其实原稿本就如此，回图才确认它改对了）；④ 把子代理列的「判不了 / 原稿笔误」条目汇成清单，交付时单列给用户核原笔记本。
10. **收尾**：建 `笔记/00-总览.md`（列各章、按主题分节；正课与习题课各一份）+ 课程 `_索引.md`（笔记 + 按主题分组的概念页清单）+ 更新学科 `_索引.md`；原 PDF 归档到 `/mnt/e/书籍/<学科>/<课程>/`（并入既有子目录，别新建顶层），清空下载目录，删掉 agent 的转写中间产物。

**量级参照**：约每 3 页原稿 ≈ 1 篇笔记。本轮 113 页正课 → 41 篇（约 5000 行）+ 121 个概念页；79 页那份 → 20 篇 + 100 个左右概念页。若某一章没内容、或明显与邻章重复，先回看切分点，不要硬凑。

## 复核存疑点的判读手法（2026-10-03 分析I 实战：5 个遗留疑点逐条定案）

要逐条给「上一轮留下的存疑点」下结论时，**别反复整页重看**——按下面这套客观手法定点判，省 token 也更硬：

### ① 先查原生分辨率，别再靠提高渲染 ppi 求清晰
```bash
pdfimages -list -f 50 -l 50 in.pdf     # 报出的图像像素 = 扫描件真实信息量
```
本次 CamScanner 档约 2300×3500 → **≈300 ppi**：**渲染 600/800 dpi 只是插值，不含更多信息**。要看清只有两条路：**裁得更小**、**点采样放大**。
```bash
pdftoppm -f 50 -l 50 -r 600 -png in.pdf hi/     # 渲染（像素平滑，便于放大看形）
pdfimages -f 50 -l 50 -png in.pdf nat/          # 原生像素（无插值，判笔画最真）
magick hi-50.png -crop 800x130+1000+2605 +repage -filter point -resize 400% w.png
```
- `-filter point`（最近邻）保留像素台阶，比默认插值更容易判「一笔还是两笔」；
- **送给视觉模型的图别超 ~30 万像素**（工具会自动降采样，白放大）：**宁裁小、别放大整页**；一次只看一处。

### ② 判据要客观化
- **数字符个数 → 列方向墨迹簇计数**（阈值化后按列统计、分簇）。本次用它确认加号右边**只有两个**墨迹簇，从而否掉其他读法。
  ```bash
  magick z-50.png -crop 1050x100+950+2372 +repage -colorspace gray -threshold 62% -negate -resize '1050x1!' txt:- \
    | python3 -c "...按列值 >=8 分簇打印..."
  ```
- **等尺寸框比墨迹像素数**（判 `≥` vs `>`、`≤` vs `<` 这类只差一根横杠的符号；多一根横杠 ≈ 多 25–35% 墨迹）：
  ```bash
  magick z-31.png -crop 110x95+2145+935 +repage -colorspace gray -threshold 62% -negate -format '%[fx:mean*w*h]' info:
  ```
  **但符号只有十几像素时仍会摇摆**——那就老实报「判不了，请你回看原稿」，不要硬改。
- **字形对照**：同一页里**同一字符**是最好标尺（判结论里的 2 与 x，就拿同页 `f(x)` 的 x 比对）。**手写体的 x 常写成卷曲形，极易被读成 2/z**；本次一度把 `x⁴` 读成 `2x⁴`，靠「同页已知 x 字形」才算清。
- **定位用低 dpi 整页、判定用高 dpi 局部**：150 dpi 整页足够看清「这页讲什么、目标在哪一行」，定位后再 600 dpi 定点裁，别一上来就整页高 dpi。

### ③ 三类结论的处置
- **原稿本身笔误/自相矛盾**（本次：分支 $x+2x^4\sin\frac1x$ 与结论 $f(x)=2x+o(x^3)$ 数学上不相容）→ **照录原文 + 报告请用户定**，不替他改（他可能记得课堂上写的是哪个）；
- **原稿与笔记一致**（本次「复数」、$y(0)=y(1)=0$）→ 不改，报告写明「原稿即如此」并给字形依据；
- **笔记读错**（本次 09 篇 `f:I\to\mathbb R` 实为空心 𝕂）→ 改，并给依据。

### ④ 法国体系的 𝕂 与 ℝ 怎么分
老师把 **ℝ 写成「带双横的 I + R」两个字符**，**𝕂 写成单个空心 K**（竖笔 + 两条斜臂）。判读时**先数字符数**（一坨是两个字符还是一个），比看笔画可靠。本次据同页 `𝒞ℳ([a,b],ℝ)`（两个字符）与 `f:I→𝕂 连续`（一个字符）区分开，把 09 篇三处 `f:I→ℝ` 改回 `f:I→𝕂`（同页 Cor `∃!f:ℝ_+^*→ℝ` 仍保留 ℝ，**勿全局替换**）。
