> 管**结构层**（定义、定理、证明各该有哪几句）的是 `references/prose-exemplars.md`——

## 为什么需要这份文件

agent 的默认失败模式是**把严格等同于符号密度**：正确性靠堆符号撑出来，可读性归零。
用户 2026-10-22 的原话：「你这也太区了，话说不清楚，证明也绕一圈」「表达能力离人类太远……
或许谈不上错，但实在难以阅读」。他要的是**能一口气读下去的数学**，不是能过审的 LaTeX。

## 硬规则

1. **能不用符号就不用**（Halmos《How to Write Mathematics》：「The best notation is no notation」）。
   检验：把符号换成中文名词，句子还成立吗？成立就换掉。
   允许保留符号的地方：一句话里出现三次以上的对象、需要做运算的那一步。
2. **一句话一个断言。** 一句里不出现两个「所以 / 于是」；一个句子不超过一个从句。
3. **主语是数学对象，不是「我们」或「这」。** 写「中心化子只有奇数个元素」，不写「我们现在来看中心化子」。
4. **结论在前，理由在后。** 读者先知道要证什么，再跟着走。
5. **符号只在定义处解释一次**，之后当名字用（「中心化子」「支撑」「长度 d 的那一组」），不再反复念公式。
   一条消息里独立算式不超过两个；三个以上说明该拆成图，或该改写成话。
6. **例子先于一般。** 先拿最小的具体情形（n=3、n=4）走一遍，再抽象。
7. **不许用「显然 / 容易看出 / 类似地」盖住跳步。** 要跳就说跳在哪、谁补。
8. **段落 = 一个动作。** 每段第一句说这段要干什么。
9. **先说「这步在干什么」，再写它。** 每步开头一句人话（「现在要把 τ 的奇偶算出来」），公式跟在后面当证据。

## 反例 → 正例（2026-10-22，群论第五题的真实素材）

反例（符号堆砌）：

> 于是 sign(τ) = ∏_{d 奇} sign(π_d) · ∏_{d 偶} (−1)^{Σ c_i}，代入你的假设，那两个乘积各自如何？

正例：

> τ 的奇偶只由两件事决定：偶数长度的循环里转了几格，一对等长循环之间搬了几次。
> 你的假设把这两件事同时掐掉了：没有偶数长度的循环可转，每种奇数长度又只有一条循环可搬。
> 所以 τ 只能是偶的。

差别不在严格性，在**主语与次序**：正例每句都在说「什么东西怎么样」，反例在报一串记号。

## 论证的形态：法国题式的小结论链（2026-10-22，用户最终定下的形态）

用户原话：「人类描述一个论述比较正常的思路应该是像我之前那样『如果左边不成立，那么 $S_n$ 中中心化子奇，从而等于 $A_n$ 中中心化子』……
你只要讲出证明中的几步概要，就想法国人出题目一样，用几个小结论拼出最后的结果就行。如果我问你某一步怎么来的，再把那一步拆开。」

要点：

1. 交付形态 = **3–5 条小结论**，每条一两句，编好号；最后一句说明它们怎么拼出命题。
2. 每条只写「断言 + 一句依据」，不展开计算；被问到时才拆那一条。
3. **不造隐喻词。** 2026-10-22 用「搬」「转」描述循环上的作用，被判定为「明显是机翻表达」。
   用现成的数学说法：把一条循环送到另一条同长度循环；一条循环上能与它交换的作用只能是它的幂。
4. **分行 ≠ 分段。** 把一堆论述一句一行排开，仍然是一堆论述（用户 2026-10-22 当场指出）。
   判据：每条小结论能不能单独抽出来当一个引理？不能就是没拆到结论层。
5. 反问自检：这版能不能直接抄进法国讲义当 1) 2) 3)？不能就重拆。

## 分段的形态：人的推理长什么样（2026-10-22 用户补的）

用户的观察：「人类平时推理时一般不会把一段论证糊在一起，而是比较简单的逻辑链条」。
根因确实在训练分布：论文是**结果导向**，过程已被压缩（作者验证过了）；人的推理是**过程导向**，
每个动作完都停一下看它给出什么。用户要看的是后者。

具体做法：

1. **一段只做一件事**：一个动作 + 它给出的结论。超过 4 行就该拆。
2. **段间报状态**：每段末尾（或下段开头）说一句「现在的问题变成什么了」/「还剩什么没证」。
   论文里没有这种句子，人的推理里到处都是。
3. **允许过程句**：写「我先试 X」，X 失败了就写「这条走不通，因为……」再换。
   这种句子在论文里被删光，但正是他想看的判断痕迹。
4. **禁止三层嵌套**（「因为 A，而 A 使 B，从而 C」）：把每一层放一段，宁可多分几段。
5. **一段里只能出现一次「所以」**（超过就是把几句话混进一句了）；脚本会报。

两条自检：这段是「已经验证完的结论」还是「正在走的一步」？如果混在一起，拆开。
把符号换成中文名词，句子还成立吗？

## 动词：英译中的高发区（2026-10-22，用户点破「送 = send 的机翻」）

中文数学有自己的动词，多数场合不是英文动词的字面对应。他原话：「一般说把 a 映到 b 什么的，送跟『映射』之类的词毫无关系，显然是 send 的机翻」。

| 英文 | 别写 | 写 |
|---|---|---|
| send / map to | 把 A 送到 B | 把 A 映到 B；A 映为 B |
| carry (is carried to) | 被送到 | 变到 / 映为 |
| induce | — | 诱导 |
| give / yield | 给与 | 给出 / 得到 |
| preserve | 保留 | 保持 |
| respect the structure | 尊重结构 | 与结构相容 |
| act on | — | 作用在 |
| commute with | — | 与…交换 |
| restrict to | — | 限制到 |
| extend | — | 延拓 |
| lift | — | 提升 |
| descend | — | 下降 |
| glue | — | 粘合 |
| vanish | 消失 | 取值为零 / 化为零 |
| kill | — | 消去 |
| realize | — | 实现 |
| identify A with B | 认同 | 把 A 与 B 等同 |
| factor through | — | 经…分解 |

自检一句：写「把 X 送成 Y」之前先问，中文里有人这么说吗？拿不准就换成「映到」「变到」「成为」。脚本的「直译动词」规则就是盯这几个词。

## 写完后的三道自检

1. 把符号换成中文名词通读一遍；读不通的句子就是符号过量。
2. 数一数每条消息里有几个算式。超过两个就砍。
3. 假设自己是第二天重读的人：哪一句需要回头再看一遍？那句要拆。
4. 跑 `python3 ~/.hermes/skills/research/math-coach/scripts/prose_lint.py -`（读 stdin 或给文件路径）：必须改的条目清零才发；标 `(?)` 的提醒级自己判断。

## 外部材料评估（2026-10-22 查过，实测数据）

- **Halmos,《How to Write Mathematics》**（免费 PDF）：唯一真正的硬规则来源，「no notation」那条出自此处。
- **Froskekongen/agent_mathematician**（MIT，0 star，最后推送 2026-09）：`mathematical-integrity` 与
  `explain-mathematics` 讲「从读者已知出发、定义在需要时才引入、把时间花在读者最不可能自己重建的那步」。
  方向对，但只到**内容组织**层，没有中文句法层、没有对照示例；0 star = 无社区验证。
- **jmf-enigma/or-ms-writing-skill**（8 star）：唯一覆盖「语言层」的（搭配、句子节奏、翻译腔修复），
  但对象是英文学术论文，不是中文对话。
- 结论：**没有现成的「中文讲数学像人话」skill，这个位置是空的**；规则只能自己写（即上文）。
