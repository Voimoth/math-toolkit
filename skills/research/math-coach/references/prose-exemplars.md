# 中文数学表述的范本：殷浩与于品

用户 2026-10-22：「关于怎么样算好的汉语表述，我也表达不清楚。你可以自己学习一下殷浩的几份讲义，
以及于品的数学分析什么的。这几本书都是我觉得把中文写得很清楚的。」

所以这份文件不是抽象规则，而是**两位作者的原文手法库**。`mathematical-prose.md` 管句法与动词，
这份文件管**结构层**（定义、定理、证明各该有哪几句）——脚本查不出来的那一层。

两份都是**中文讲义**、都有法文术语穿插（殷浩：adaptée、suites récurrentes；于品：把法文原句放脚注）。

## 十二条手法（每条附原文短引）

### 定义页

1. **定义之后紧跟一句「重新解读」**，把形式条件翻成人能用的判据。
   > 于品：「注记. 我们可以重新解读后两条性质：「⋯⋯」第二条等价于说，如果 x₁ ∈ X，那么对任意的 x₂ < x₁，
   > 我们就有 x₂ ∈ X。」
   用法：定义写完，立刻问「这个条件实际拦住了什么 / 允许做什么」。

2. **例子说清它干什么用**，不堆三四个无名例子。
   > 于品：「这个例子将给出所有的有理数。」「这个例子将给出我们所熟悉的 √2。」

3. **承认简化与代价**，不装作一般情形都做了。
   > 于品：「我们满足于 V = Rⁿ 是有限维的情形。」
   > 殷浩：「我们不会真的把这门课建立在几个公理之上。虽然理论上可以，但是没有 必要。」

4. **术语出现即给对照，之后只用一种叫法**（殷浩把法文括在括号里：适应 (adaptée) 于 f）。

### 定理页

5. **定理之后必答「它拿来干什么 / 和已知的什么是一回事」**，这就是他们的「注记」。
   > 于品：「注记（Fubini 用来交换积分顺序）。除了在计算积分时可以降维之外，Fubini 定理还有其它的应用：⋯⋯」
   > 于品：「注记. 我们所寻求的高维的积分理论一定要具备两个基本的工具：第一，Fubini 定理⋯⋯第二，
   > 换元积分公式⋯⋯所以，从计算积分的观点来看，我们所得到的理论和 Riemann 积分实际上差别不大。」
   用法：讲完一条定理，用两句话说「它在整个课程里替谁干活」。

6. **记忆窍门与证明分开标注**。
   > 于品：「注记. 记住（不是证明）上面的公式可以用如下的窍门：将 y = Φ(x) 直接代入左边⋯⋯」

7. **边界单独一行「注意：」**，一句话，不附证明。
   > 殷浩：「注意：这个定义对分点处的取值毫无约束。」
   > 殷浩：「注意：上面的结论不能推广到严格不等式。容易举例。」

### 证明页

8. **第一句先把情形削到最小**：退化情形先砍掉，再声明只证剩下的。
   > 殷浩：「证明. 注意 n = 1 不用证。」「证明. 极端情况略。只考虑右边是正实数，设为 σ。」
   > 殷浩：「证明. 分点总共有限多，只要证明在每个 (uᵢ, uᵢ₊₁) 上有界就好了。」

9. **目标写成「往证 X」或「只要说明 Y 即可」**，不复述定理。
   > 殷浩：「往证 R = σ⁻¹。」
   > 于品：「我们假设 X ⊄ Y，只要说明 Y ⊂ X 即可。」

10. **技巧点当场点名**，让读者知道哪一步是关键的。
    > 殷浩：「（这就是改进所在，通过让他们两个是有理数，进而后续的数列都是。）」

11. **括号承载限定语、出处、口语补充**，不打断主线：
    > 殷浩：「（这里有界是，有一个有理数界。具体的，看证明就知道了。）」「（某位同学提醒我）」
    > 「（上节课做过了）」「（略）」「（重难点）」
    用法：一句话讲不透又不想开新段的东西，全塞括号。

12. **允许过程句与设问**，中文数学不是只有陈述句：
    > 殷浩用设问当小标题：「公理？」「集合？」「严密？」；段首用「接下来详细一点。」
    > 于品：「比方说，给定 R 上的区间 J = [0, 1]⋯⋯」

## 三位一体的骨架（照着填就不会写成符号堆砌）

```
【定义】形式定义（一两行）
        → 重新解读：这条件实际允许什么、拦住什么
        → 一个例子，并说明它给出的是哪一类对象

【定理】陈述（只写条件与结论，不加动机）
        → 注记：它替课程的哪一步干活；与已有结论的关系
        → 注意：边界情形在哪失效（一句话，不证明）

【证明】先削：哪些情形不用证、只证剩下的哪个
        → 往证什么（写成一句可检验的断言）
        → 关键一步点名（「这就是改进所在」）
        → 收口：剩下的情形怎么回到已削掉的部分
```

## 这两位**不**做的事（正是 agent 的默认毛病）

- 不写「本节的目的」「综上所述」「由此可见」这类导语／收尾套话（也见 `lint_natural_chinese` 的 `sum_*` 规则）。
- 不用「本质上是」给结论加抽象包装——直接写关系（vault 里 14 处这类句子 2026-10-22 已全部改成直陈）。
- 不在证明里复述定理条件；条件只在「往证」那句里出现一次。
- 不把一行算式当一句解释；每个公式前面有一句人话说它在算什么。
- 不用生造隐喻（「送」「搬」「转」）代替数学动词。

## 怎么用

1. 写一段中文讲解前，扫一眼上面十二条，问自己缺了哪一类句子（定义缺重述？定理缺注记？证明缺「往证」？）。
2. 写完跑 `scripts/prose_lint.py`：它只能查句法与模板句，**结构层要靠这张表自检**。
3. 用户说「难以阅读」时，先按第 8、9 条检查证明开头，再按第 1、5 条检查定义／定理之后有没有解释句。
4. 要对照原文时直接抽这几份 PDF：`pdftotext -layout -f A -l B <pdf> -`，三份都有文本层。
