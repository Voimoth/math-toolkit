# bookdex：参考书目录索引

## When to Use

- 他问「哪本书讲过 X」「有没有讲 YY 的参考书」「这个概念哪本书处理得更严格」
- 要在一批书里挑一本深入读，但不知道挑哪本
- 不要在「已知是哪本书、只缺页码」时用（那是 `pdf-problem-search`）

**定位**：不抽正文，只索引**书名 + 作者 + PDF 书签目录**。回答「哪本书可能讲这个、第几章」；
精确定位到某页交给 `pdf-problem-search`（单本 + pdftotext，实跑过 118 次）。

**分工**：
- `bookdex` = 不知道在哪本书 → 给候选书单 + 章节标题 + 页号
- `pdf-problem-search` = 已知是哪本书 → 定位到具体题面/定理

## 位置与命令

```
~/.local/share/bookdex/
  venv/       # python 3.14 + pymupdf 2.0
  index.py    # 建/增量更新书目卡
  query.py    # 查询
  index.db    # SQLite，一本一行
  aliases.tsv # 手工别名表（作者/俗称 → 路径），查询时自动并入
  README.md   # 面向使用者的说明（随 math-toolkit 的 tools/bookdex 一同发布）
```

```bash
B=~/.local/share/bookdex
$B/venv/bin/python $B/index.py                 # 增量（跳过未变的）
$B/venv/bin/python $B/index.py --rebuild       # 全量重建
$B/venv/bin/python $B/query.py "正规子群"
$B/venv/bin/python $B/query.py "variational principle" --limit 15
$B/venv/bin/python $B/query.py "subgroup" --json
```

## 找书的第一动作：查 bookdex，不是 find

2026-10-22 的事故：用户说「于品的书没道理本地没有」，我先用 `find` / `grep` 扫文件名，得出「本地没有」，
实际上书在 `数学专业书籍/数学分析/Analysis123.pdf`。文件名里没有作者名，**用文件名搜索永远找不到**。

顺序固定为：

1. `query.py "词"`：概念、书名、作者（作者走 `aliases.tsv`）、法文术语都先在这里查。
2. 只有给了**纯主题词且零命中**时，才 `find <限定子目录> -maxdepth 4 -name '*关键词*.pdf'` 补充。
3. 两步都空，才能说「没找到」——而且要说「书名/目录里没有」，不要说「你书库里没有」。

## 作者/俗称搜不到：aliases.tsv 与目录名命中（2026-10-22 加）

索引能拿到的只有书名、书签目录、目录页文本；**作者往往不在任何一处**（PDF 元数据多为空，
`Analysis123.pdf` 更是连书名信息都没有）。两处弥补：

- **目录名命中（+2 分）**：文件名没用时，主题只能写在目录里。实测 `数学分析` 召回 339 → 375 本，
  `Analysis123.pdf` 从第 89 位升到第 3 位。
- **`aliases.tsv`（+8 分，相当于书名命中）**：一行「查询词⇥路径片段」，多个片段写多行，`#` 是注释。
  改完即时生效，**不用重建索引**。现置条目：`于品` / `Yu Pin` / `丘班` → `Analysis123.pdf`；
  `殷浩` → `分析/分析I/分析I(` 与 `分析/分析II/分析II(`（上下册各一行）。
- 输出里别名命中会明写「按别名表命中」，**不冒充书名命中**（JSON 里是 `alias_hit` / `dir_name_hit`）。
- 新书入库时若文件名不具信息（`Analysis123.pdf` 这种），**当场补别名（作者 + 主题）**；
  否则这本书在检索里等于不存在。

## 层级权重（tier，2026-10-20 用户要求）

不是所有书等重。三层，`index.py` 的 `ROOTS` 决定基础层，`TIER_HINTS` 按路径往上提：

| tier | 范围 | 查询倍率 |
|---|---|---|
| 3 | 课程在用：`/mnt/e/书籍/{代数,分析,物理,数学学习方法}` | ×2.2 |
| 2 | MPSI 预科：路径含 `MPSI` / `Mathématiques MP/PSI`（中法班大部分数学课的直接参考） | ×1.6 |
| 1 | 普通参考书：`数学专业书籍` 那 8000 本 | ×1.0 |

排序分数乘 `1 + 0.6×(tier−1)`，**用乘法不用加分**：查一个课程书里根本没有的词，它仍然不会冒出来。
输出里课程书标【课程】、MPSI 标【MPSI】。

## 无书签的书：目录页兜底（2026-10-20）

有书签的只有 42%，剩下的按成本分三层，**不要一律上视觉模型**：

| 情况 | 做法 | 成本 |
|---|---|---|
| 无书签但**有文本层**（约 3100 本） | 取前 20 页文本存 `dir_text`（`dir_src='text'`） | 精确、几乎免费 |
| 全盲扫描件（实测 1459 本） | tesseract OCR 前 20 页 | 单本实测 18 秒；6 并发约 5 小时（见坑） |
| OCR 也读不出的少数 | 这才值得上视觉模型（vision_analyze） | 按本计费 |

**OCR 语言按资料语种选**（`ocr_lang()`）：文件名含中日韩 → `chi_sim+eng`；路径/文件名带法语特征
（重音字符，或 mathématiques / exercices / oraux / algèbre / analyse / MPSI / polytechnique 等词）→
`fra+eng`；其余 `eng`。**判语种前先剔掉路径里的中文目录名再匹配法语特征**，否则 `/mnt/e/书籍/…`
的中文会把所有法文书判成中日韩。法文必须走 fra：`eng` 会把 `théorème` 认成 `theoreme`，
带重音的法文查询就永远命中不了（2026-10 实测）。

**扫描仪垃圾书签**：有些扫描件自带 `01` / `202512280213` 这类时间戳书签（全库 51 本）。
判据是 `toc_junk()`：所有标题都只由数字/空格/`-_.:/` 组成。这种书按「无书签」处理，照样抽目录页——
否则 300 页的书在检索里只剩个文件名。

实测质量：英文扫描件 tesseract 几乎逐字正确（Goursat《数学分析》卷三）；中文能认出章节行但带错字
（《统计学》第 6 版「5.6 判定正态性的描述性方法 716」对、「15:4」应为 15.4）。
所以 OCR 文本**只作召回**：命中时输出「无书签；前 20 页 OCR 目录页里出现该词，自己去翻」，
**绝不冒充章节页码**。`dir_text` 命中权重只有 2.5，远低于真书签命中。

## 查询纪律

**重音必须归一**：`query.py` 的 `fold()` 把查询和字段都做 NFD 去重音（并折 `œ→oe`），
所以 `théorème` / `theoreme` / `théoréme` 互通。不要退回「用 `[^0-9A-Za-z]` 分词」的老写法——
那会把 `théorème` 切成 `th`+`or`+`me`，法语查询静默失效（2026-10 实测：改成 fold 后
`théorème` 命中从 1 本变 124 本，`Algèbre` 从 0 本变 74 本）。

- 给 **3–5 本候选**即可，别倒书单。命中章节带 PDF 页号（1-based 物理页），让他自己翻。
- 找不到只能说「**已索引的书名/目录里**没命中」，不能说「你书库里没有」——目录缺失、扫描件无书签都是覆盖状态。
- 书目级命中不等于「这页就讲了你要的定理」：需确证时再走 `pdf-problem-search`。
- 公式别转述。目录标题可以引，正文要他自己看。

## 用在辅导里（与 math-coach 联动）

用户 2026-10-20 明确要求：辅导时**可以告诉他参考书让他自己去看**。规则本体写在 `math-coach`
的「参考书指引」节，这里只记工具侧：

- 一段概念讲完、或他问「哪里更严格 / 更全」时才查，**不是每轮都查**；查不到对口的不提。
- 给他「书名 + 章节 + 页号」，让他自己翻；**不许**把命中的章节标题改写成讲解（违反 math-coach A3）。
- 优先课程书与 MPSI（tier 3/2）：他手头有纸本的才叫参考书。
- `bookdex` 命中的是**目录**，正文是否真讲还得他翻 —— 别把候选说成结论。

## 坑（都踩过）

- **书名不具信息的书在索引里是隐形人**。`Analysis123.pdf` 就是于品《数学分析》：名字无信息、元数据作者为空、
  133 条书签全是章节名。改前查「于品」命中 3 本全是噪声，真书一本没命中；`数学分析` 里它排第 89。
  现在的答案是**目录名命中 + aliases.tsv**，别再试图从内容里“推测作者”。
- **改 `index.py` 前先 `pgrep -f index.py`，确认没有后台增量在跑**。长增量会被前台超时提升成后台进程，
  它加载的是**启动时的旧模块**；代码改完之后它还在写库，会把旧逻辑的结果（语言标签、dir_text）盖在新结果上，
  而 Hermes 只会在它退出时发一条回执，很容易被当成无关通知忽略。正确流程：杀/等完残留进程 → 改代码 → 单测 →
  清 `dir_src` → 重跑 → **用当前 `ocr_lang()` 校验全库标签一致性（不一致应为 0）**。别只看总量或抽查两本书。
- **改 `ocr_lang()` 时别把整条路径交给 CJK 判断**：中文目录名（`/mnt/e/书籍/…`）会让所有书被判成中文，
  法语扫描件就被 `chi_sim+eng` 坑一遍（正确做法：CJK 只看 basename，判法语前先把路径里的中文剔掉）。
  改完先单测：`venv/bin/python -c "import index; print(index.ocr_lang('/mnt/e/书籍/数学专业书籍/Oraux X et ENS（7卷）/x.pdf'))"` 应为 `fra+eng`。
- **重做已有卡的 OCR 要手动清 `dir_src`**：增量只处理 `dir_src=''` 的书，改完语言不 `update books set dir_src='' where …` 就白改。
- **文件名含空格与中文**：shell 里遍历必须 `find -print0` + `IFS= read -r -d ''`。用 `for f in $(find ...)` 会把「GTM172-Classical Topics in Complex Function Theory」拆成 5 个假文件，抽样结论全废（我第一次就报错成「20 本 → 53 次」）。Python 里用 `os.walk` 没有这个问题。
- **`._xxx.pdf` 是 macOS 的 AppleDouble 资源叉**，0 字节。磁盘上有 15 个，`pymupdf.open()` 全部报错，会在统计里冒充「打开失败」。遍历时跳过 `startswith("._")`。
- **英文不能只写 `\b前缀`**：`\bRiemann` 会命中 `Riemannian`、`Riemann-Stieltjes`，查 `Riemann-Roch` 的命中数从 42 涨到 382，前几条全是噪声。正确做法：单词用 `\bWORD(?:s|es)?\b`，多词走短语并把词间写成 `[\s\-–—]*`（这样 `Riemann-Roch` / `Riemann–Roch` 都能配）。
- **封面/版权页的目录条目要降权**：书签里 p.1–p.5 常把书名重复一遍（「中文版 复分析：可视化方法」），看起来命中其实零信息。`page <= 5` 权重压到 0.2。
- **书名命中的权重必须够大**（现在 +6）：否则查「复分析」时，一本正文里提了一句复分析的微分几何书会压过 Rudin《实分析与复分析》。这是两条不同的检索意图——书名型 vs 概念型——靠权重区分，不要靠排序巧合。
- **建库速度别用抽样外推**：30 本抽样 100 ms/本 → 外推 13.5 分钟；实跑 **666 秒**（12 本/秒）。中途我还误判过一次「2 本/秒要跑 1 小时」，原因是 `index.py` 每 100 本才 commit，我拿两次 DB 行数比对当成了处理速度。看进度要读 stdout 的百分比行，不要读 DB 行数。
- **只读元数据**：`pymupdf.open()` + `get_toc()` 不解析页面，比 `pdftotext` 整本抽取快两个数量级。也别去 `pdftoppm`。
- **中文不分词**：query 用子串匹配（`'正规子群' in title`），8000 行读进内存过滤已是毫秒级。别引入 jieba/FTS5 那套（旧 RAG 就是这么烂掉的）。
- **书签里的控制字符**：实测有 `正规子群和同态\x00` 这种，显示前要 `re.sub(r'[\x00-\x08\x0b\x0c\x0e-\x1f]','',s)`，否则终端里出现乱码方块。
- **tesseract 走 stdin，别落盘**：`page.get_pixmap(dpi=150, colorspace=csGRAY).tobytes("png")` 直接喂 `tesseract stdin stdout -l …`，省掉 `pdftoppm` 的临时文件；实测 20 页 18 秒/本。
- **OCR 不要全量上视觉模型**：1500 本 × 每本 2–3 次调用，比 tesseract 贵几个数量级，而中文 OCR 的错字对「搜索召回」无害、对「精读」有害——那就不是它该干的活。先 tesseract，读不出的少数才 `vision_analyze`。
- **并发 OCR 别按「单本耗时 ÷ 并发数」估**：单本 18 秒、6 并发，我估 75 分钟，实跑 **5.3 小时（差 4.6 倍）**。日志看得很清楚：前 200 本 190 秒（文本层快书），到 3000 本已 11600 秒，速度从 1 本/秒掉到 0.23 本/秒。主因推测是 6 线程同时随机读 USB 移动盘 + 6 个 tesseract 抢 CPU（没有单独做消融）。要估就先用 100 本小批实测折算率，别拿单本数乘除。
- **`dir_text` 的页码信息被丢了**：早期版本用 `\n` 拼接 20 页，所以命中只能报「在前 20 页目录里」，报不出页号。要精确到页就改成 `\f` 分页存（重建时改，查询按 chunk 序号算页）。

## 为什么拆掉了全文 RAG

旧的 `math-rag`（FTS5 页级全文索引，208 本/7449 页）2026-10-02 建成，10-20 拆掉，**18 天里零次真实检索**：
`state.db` 统计 `query.py` 只被调过 9 次（6 次是建设当天自测），同期 `pdf-problem-search` 47 次、`pdftotext` 118 次。
不是质量问题而是场景错配：

1. 他的提问多是「课程里的某个概念/某道题」，书已知 → 缺页码，不缺书。
2. RAG 能交的产物是「书上是这么写的」，而他的教学要求明确禁止把讲义/检索结果改写成通顺总结 → 检索到了也不该那样交付。
3. 全量全文索引 125 GB 要几小时 + 几十 GB 空间，扫描件占 35% 永远搜不到。

结论：**书目级检索解决「找对书」，这才是真缺口**；页级全文只在单本确认时才需要。
