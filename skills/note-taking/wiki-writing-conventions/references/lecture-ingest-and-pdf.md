# 讲义更新（课程推进）与 PDF 提取

> 摘自 `wiki-writing-conventions` SKILL.md（2026-10-03 拆分），内容未改。

用户发来同名新讲义(`sofar (1).pdf`,36 页 / 2801 行)时,第一反应是"补充第 1-3 章的细节",**方向错了**——对比旧提取文本(`sofar_extracted.txt`,17 页 / 1170 行)才发现新讲义已推进到 **§4 Cesàro/Abel 求和 + §5 L² 理论**。判断方法(别靠猜):

1. **行数/页数对比**:`Compare-Object (Get-Content 新.txt -Encoding UTF8) (Get-Content 旧.txt -Encoding UTF8)`;行数倍增 + 页数翻倍 = 新增章节,不是修订。
2. **读新目录页**:目录就是权威章节清单(新目录多出 §1.3/§3.6 历史注记、§4.1–4.3、§5.1–5.5)。
3. **按章读新增部分**;特别记下"旧伏笔被回收"(§3.4 末尾遗留的"系数决定函数到什么程度"现由定理 4.6 唯一性定理回答)——这类衔接必须写进笔记。

**覆盖面判定**:讲义推进后,原先"未学"的章节变成已学,原先按"不在范围内"带过的内容现在要落地成概念页,包括**从 git 历史恢复当年删掉的页再按新讲义重写**。恢复旧页时必须逐句核对——旧页常带硬伤(如把 Fejér 定理说成"只需连续",漏掉周期性与端点条件;把"法国体系 Fejér 先行"当成课程已讲的事实),这些正是用户纠正过的点,不能原样复活。

**不要把"新讲义"误判成"老讲义的细节增补"(2026-09-10 修正,本技能原先的建页方案就犯过)**:第一反应是"给第 1–3 章补充细节",方向错了。新讲义相对旧版的**主体增量是新章节**(§4 广义求和 + §5 L² 占 36 页里的 20 页),老章节只是顺带补了历史注记。所以产出的重心必须是**新章节的完整概念页体系**,而不是对已有页面的精修。判据:先按 4d 的页数/行数/目录三步定位边界,再按"新增哪些章 → 每章需要哪些页"列清单;**不要沿用上一轮会话留下的建页草案**(那是在当时的信息下写的,边界和页数都可能已变)——本次实测草案把 §4 引子并进 Cesàro 页、把 §5 抽象并进 L² 页,实际落地时都拆成了独立页,详见 `references/fourier-4-5-course-advance.md`。

**动手前先 `git status`(2026-09-10 实测发现上次会话的未提交删除)**:摸清工作区状态,否则会把别人留下的改动混进自己的 commit。典型残留:半删半留造成**断链**——文件已删但指向它的 `[[wikilink]]` 还在(实测 `傅里叶学习路径.md`、`傅里叶级数入门.md` 末尾都指向已删的 `[[Fourier讲义2026]]`)。发现这类残留要**向用户报告并让其决定**(保留/丢弃/恢复),别默默 `git checkout -- .` 或顺手提交。

**别被转义后的路径骗了(2026-09-10 绕了很久的弯路)**:`git ls-files` / `git show --name-status` 默认把非 ASCII 路径打成八进制转义(`\346\225\260\345\255\246` = '数')。用转义串去 `git log -- <路径>` **会静默返回空**,看起来像"这文件从没提交过"。设定 `git -c core.quotepath=false <cmd>` 或用 `git --no-pager` + `-c core.quotepath=false`,输出即为可读中文路径。核对中文路径的提交历史时这是必加项。

**查"某文件是否曾存在于仓库"**用 `git ls-tree <commit> <目录>/`(列目录树,比逐个 `git show` 快得多),配合 `git log --all --diff-filter=D` / `-S "<字符串>"` 定位删除或内容引入的 commit。



注入新讲义时先提取文本。本机(Linux)用系统 poppler,中文直接可用(2026-10-06 实测):

```bash
pdftotext -layout "<输入.pdf>" "<输出.txt>"
```

- 提取产物用完即删,别留在仓库里被 `git add` 带走。
- 提取完把结果覆盖到 `Fourier/笔记/sofar_extracted.txt`(该文件是"用户学到哪"的事实来源之一),再按 4d 的流程对比新旧行数判断课程是否推进。
