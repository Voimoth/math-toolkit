# 大编辑门槛与落盘后校验

**来源**：2026-10-07 从 `pika_math_learning_toolkit-2.1.5` 的
`obsidian-vault-notes/references/editing-protocol.md`、`large-edit-verification.md`、`math-note-style.md`
借鉴，改写成适配本机工具链（Hermes 的 `patch`/`write_file` + git + 本技能的两个校验脚本）的版本。

## 1. 什么算「大编辑」（必须先走门槛）

满足任一条就走第 2 节：

- 一次性重写/重组一个概念页的多个小节（不是补一段、改一行）；
- 新建一个超过 ~4 KB 的概念页，或整篇新写的笔记页（`NN-主题.md`，包括给既有系列追加一篇）；
- 整门课的批量转写/批量补链（先用 `math-notes-transcription` 的分段并行流程分段）；
- 任何会改动既有页面的**编号方案**（定理编号/章节号）的编辑。

**不算大编辑**（走普通 `patch` + 校验即可）：一段话的补充、一行公式修正、单个链接/标题修复、
机械替换、短小节插入。不要因为「涉及数学」「内容重要」就升级门槛。

## 2. 大编辑流程

1. **候选先出库**：把完整目标文本写到 vault **之外**（`~/.hermes/cache/scratch/` 下），不在 vault 里原地长。
2. **在候选上跑全部确定性检查**（见第 3 节），拿到 `候选 sha256`。
3. **独立评审**：派一个**无上下文子代理**（或另起一个干净会话）按「这个候选与原意是否一致 + 是否有数学/格式错误」
   审一遍，要求它给出「发现清单 + 判定」并引用候选的 hash。评审者**不得**修改 vault。
   —— 它没有我的会话历史，也没有「我刚写完所以它应该对」的偏见。
   派活时**把原始材料的路径一并给它**（原 PDF 的 `pdftotext` 提取文本、原图目录）：否则它只能核「内部自洽」而核不了「与原文相符」，而忠实度恰是这类整理里最容易错的地方。要求它开头引候选 sha256、按「错误 / 格式 / 表述」三类列发现并给一句话判定。
4. **写入**：用 `write_file` 落盘（Hermes 会在写入后跑 hash 确认；返回 `verified:true` 才算写成）。
5. **落盘后复核**：重跑第 3 节的检查 + `git diff --stat` 看改动范围是否就是预期的那些文件。

**三轮不过的例外**：若连续 3 轮评审都没过，第 3 轮候选可以按「已知有未解决问题」的状态落盘，
但**必须在回复里写明还剩哪些未解决问题，且不许把它说成「已通过评审」**。

## 3. 落盘后必跑的确定性检查（不许用「我自己数了一遍」替代）

```
python3 <技能目录>/scripts/check_wikilinks.py /mnt/e/notes        # 四类链接问题，全 0 才干净
python3 <技能目录>/scripts/lint_natural_chinese.py <改动文件>      # 中文自然度/改动过程泄漏
```

另外三条（脚本覆盖不到的，必须人工核）：

- **表格单元格里的 wikilink alias 要转义**：`[[目标\|别名]]`、`![[图.png\|300]]`。
  单元格里的裸 `|` 会在 Obsidian 解析链接之前就终止单元格 —— **链接目标存在也不代表渲染正确**。
- **数学分隔符**：`$…$` / `$$…$$` 成对，不出现 `\(…\)` / `\[…\]`；短公式别被拆成独立段落（见 SKILL.md §4）。
- **TeX 控制词 shadow（反斜杠丢失检测）**：同一页里若 `\name` 在别处出现、而某处只剩裸 `name`，
  多半是转义在传输中丢了一层。**这条是通用检测器，但替代不了「用原始通道传 TeX」**：
  一个只出现一次的孤立反斜杠被吃掉后，从最终文本里已经推不出来。
  所以写数学内容时：**TeX 当数据传**（用 write_file 直接写文件，别经过会解释转义的中间字符串）。

## 4. 改动过程的表述纪律（与本 vault 的铁律同源）

- 页面里**不写「本节新增/修正了…」**（`lint_natural_chinese.py` 的 `edit_leak` 类会抓）。
  描述对象现在是什么，而不是这次改了什么。改动日志进 `log.md`，不进正文。
- 既有页面上**先存在的段落一律当成用户的**：改动只碰目标区间，重写整页时必须逐段交代被替换掉了什么。

## 5. 证明状态标签（写在正文里的用法）

只在**真有用**时加：`已证明` / `证明草图` / `待检查` / `猜想·启发式`。

- 正式 callout（`[!note] 命题/定理/引理/推论`）里**不放**「证明状态：已证明」这类行——那里只放数学陈述本身。
- 状态行写在 callout **外面**的正文里，且只在「不加会让人误读」时才写。
- 不确定的推导、凭记忆写的定理陈述**必须显式标注**，不许把不确定磨平成自信的证明。
- 正文里要分清三件事的来源：**笔记里已有的 / 从相邻笔记检索来的 / 这次新推断的**。
