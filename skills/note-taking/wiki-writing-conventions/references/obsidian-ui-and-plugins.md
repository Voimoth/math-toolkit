# Obsidian 图谱配色与社区插件

> 摘自 `wiki-writing-conventions` SKILL.md（2026-10-03 拆分），内容未改。

用户要求"笔记一个颜色、各学科概念分别不同颜色"。**不必开 GUI**,直接改 `/mnt/e/notes/.obsidian/graph.json` 的 `colorGroups` 数组;改完让用户 `Ctrl+P` → Reload app(或重开图谱视图)生效。

### 关键机制(决定配色成败,全部实测)

1. **按数组顺序取第一个匹配的组** —— 一个文件只得到它命中的**第一个** query 的颜色。**顺序即优先级**:"笔记"必须排最前,否则 `path:代数III` 会把它目录下 `笔记\` 里的文件一并染成概念色。
2. **用 `path:` + 单个中文特征词,不要带 `/`** —— `path:` 是**子串包含**匹配。写 `path:代数III/概念` 这种带斜杠的形式**实测命中 0 个**(本地 `\` 与 Obsidian `/` 的语义不一致,子串匹配也不吃这种组合)。改用不含斜杠的目录名(`path:代数III`、`path:Fourier`、`path:理论力学`、`path:笔记`、`path:_索引`)最稳。
3. **`file:` 只匹配文件名,中文 vault 里通常分不了学科** —— 本 vault 概念页文件名不含课程名(`群.md`、`傅里叶级数.md`),学科着色**必须靠 `path:`**。
4. **颜色值是无符号十进制整数**(`(r<<16)|(g<<8)|b`),不是十六进制字符串:写 `"rgb": 14701138`,不是 `"#E05252"`。
5. **色相必须分开**:第一版把 Fourier 与理论力学都配成绿(`#00934A` vs `#43A047`)撞了色 —— 写完要**解码回 HEX 去重检查**(唯一色数须等于组数)。

### 本 vault 的既定配色(已定稿,照此维护)

**2026-09-11 用户确认版**。经三轮反馈才定稿,每轮的驳回理由都值得记住:

1. 初版笔记给灰 `#9B9B9B` → 用户:「醒目一点」
2. 改洋红 `#E91E63` → 用户:「和代数概念的颜色区分度比较低」(洋红 338° vs 红 0° 只差 22°)
3. 按**课程级**分色(代数III/Fourier 各一色)→ 用户驳回:「什么代数III之类的分类太细了,到时候找不出这么多颜色用」
   → **改为学科级**。这是关键转向:**颜色按学科分配,不按课程** —— 学科少而稳定,课程会不断新增。
4. 用户要求给**尚未开课的概率论预留**一种颜色。

**学科级配色为什么能用单字关键词**:实测 `代数` 只出现在 `数学/代数/` 树下、`分析` 只出现在
`数学/分析/` 树下(0 误伤),所以 `path:代数`、`path:分析` 是安全的。**新增学科前先做这个误伤检查**
(遍历全库路径,确认该词不出现在别的学科树里)。

**层级效果是设计的一部分**:`分析/` 树下有 22 个文件,但只有 16 个染蓝色 —— 差额是它的
`笔记\`(被第 1 组青绿接走)和 `_索引`(被第 2 组橙接走)。用户要的正是「笔记一色、索引用一色、
概念按学科分色」这三层。

**配色两条硬约束(都踩过)**:
- **主体内容(笔记/课件)不要用灰或淡色** —— 用户要一眼区分。
- **相邻色相至少拉开 40°**,且**不要给两个语义不同的组用同一色系**。用户对「洋红 vs 红」这类
  同色系相邻配色的容忍度很低,会直接要求返工。定色前把候选色转 **Hue 值**排一遍,
  确认最小间距;`#E91E63`(338°) 与 `#E05252`(0°) 只差 22°,是反面案例。
  当前版本最小间距 = 40°(橙 40° vs 红 0°)。

**给「还没开始的课程」预留颜色是用户明确要求** —— 照样加一条 `path:<学科名>`,命中 0 个也无害,
将来该目录下建页即自动上色。挑预留色时避开已用色相。

配套显示参数:`showArrow: true`(显示连线方向)、`nodeSizeMultiplier: 1.3`、`textFadeMultiplier: -0.5`、`repelStrength: 12`、`linkDistance: 220`、`collapse-color-groups: false`(颜色面板默认展开)。

### 写入与验证纪律

- **字段集必须与 Obsidian 自己写的一致**(20 个固定 key)。加多余字段或漏字段都可能被忽略:把 `$official` 数组与解析出的 key 集做**双向差集**,两个方向都应空。
- **文件须无 BOM UTF-8**(用 `[IO.File]::WriteAllText($p,$c,(New-Object Text.UTF8Encoding($false)))`)。
- **`graph.json` 不被 git 跟踪**(`.obsidian/` 在 `.gitignore` 里,仅 `app.json` 例外且被跟踪)——改动只在本机生效、不进 GitHub;坏了 Obsidian 会重建,风险低。
- **无 GUI 的验证手法**:写 Node 脚本复现"按顺序取第一个 `path:` 子串匹配"的归属逻辑,打印每组命中清单 + 未着色清单;再把 query 特征词与磁盘真实目录名做**逐字符码点比对**(防大小写/同形字不一致,如 `代数III` 三个大写 I 的码点须为 `20195,25968,73,73,73`)。两种独立实现交叉验证通过再交付。
- **Obsidian 开着时改这个文件有被回写覆盖的风险**:写文件工具会报 `was modified since you last read it on disk (external edit or unrecorded writer)` —— **必须 `read_file` 回读确认拿到的是自己的版本**;Obsidian 在退出/切换视图时会**把内存里的图谱设置写回**,可能冲掉外部改动。所以改完提示用户**先在 Obsidian 里看一眼确认生效**;若他在图谱里拖过节点/改过缩放,退出时可能覆盖配置,必要时重写一次。
- **诚实边界**:无法脚本化触发 Obsidian 的 Graph View 渲染来端到端确认颜色真的显示 —— 它是 Electron GUI,没有查询接口。交付时**明确标注"这是逻辑推演验证,需你在 GUI 里目视确认"**,并给出回退路径(若颜色没出现,改用 `file:` + 多关键词方案)。
- **不要为"跑验证"造临时脚本**:用户明令禁止建 `hermes-verify-*.ps1` 这类文件(原话"写好了搞什么验证脚本,你当我眼瞎不会看吗"),核验一律用**内联命令**;用完的临时文件当轮删掉。配置层面验完就停下等用户目测,不要反复重跑同一套验证。

装插件无需 Obsidian GUI,可全自动:

1. **下载**:从 `https://github.com/<owner>/<repo>/releases/latest/download/{manifest.json,main.js,styles.css}` 下载到 `/mnt/e/notes/.obsidian/plugins/<插件id>/`;manifest 里的 `id` 必须与目录名一致(装完逐一核对)
2. **启用**:写 `/mnt/e/notes/.obsidian/community-plugins.json`(JSON 数组列出插件 id);用户重启 Obsidian 后需点一次"信任第三方插件"
3. **repo 名先确认再下载**:用 GitHub API 搜索(`api.github.com/search/repositories?q=obsidian+xxx&per_page=5`)看 stars 挑正主,盲猜必 404(例:recent-files 是 `tgrosinger/recent-files-obsidian`)
4. **已装(2026-09-02)**:pandoc(系统级 pandoc 3.11 二进制已 winget 装好,导出 PDF/Word 可用;装二进制后 Obsidian 需重启才能感知 PATH)、recent-files-obsidian、better-word-count(统计跳过公式)、obsidian-style-settings
5. **克制原则**:只装真有用的;数学渲染内置 MathJax 已足够,不装 Dataview/Excalidraw 等重插件
