# 对外发布配套仓库（工具库 / 技能库）

适用：把维护 vault 用的技能、编辑器配置发布成 GitHub 仓库，或把笔记库本身公开时。
核心风险不是「写得不好看」，而是**发布物里夹带个人身份信息**与**许可证盖到了别人的内容上**。

## 1. 独立成库，不塞进 vault

配套工具库**单独建库**，不要在 vault 里开 `tools/`：

- vault 是 Obsidian 库，几 MB 的 md 进去会污染搜索、图谱和 `check_wikilinks.py`（技能里的 `[[...]]` 会被判断链）；
- vault 的 pre-commit（>5 MB 拒绝、LF 锁）是为笔记设的，和技能/配置的更新节奏不同；
- 权限要能独立（工具库以后想公开，不必连带笔记）。

vault 的 `README.md` 只留一行指向该库即可，两库内容不要互相复制。

## 2. 发布前扫描（按库扫，不按工作区扫）

先用 `git ls-files` 取出真正入库的文件再扫，`.gitignore` 掉的不算泄漏：

```
grep -InE 'pb[0-9]{6,}|[0-9]{11}|@[a-z0-9.-]+\.[a-z]{2,}|/home/[a-z_]+' $(git ls-files)
```

三个高发点：

1. **同步/脱敏脚本自身**。为了替换身份信息而把学号邮箱、私人邮箱、另一个账号名硬编码进 `sync.sh`，等于把要藏的东西写在了最显眼处。做法：脚本只读 `sync/local/sanitize.sed` 与 `sync/local/exclude.txt`（`.gitignore` 掉），仓库里只留通用脚本与一个说明格式的注释头。
2. **排除表本身**。`exclude.txt` 里逐条列出「哪些个人文件不发布」，等于公开「他有哪些个人记录」。排除表同样本地化，不随库发布。
3. **绝对路径**：`/home/<user>` 一律替换成 `~`；`sources:`、脚本、配置注释都要过。

## 3. 已经泄露：重写历史

仓库刚建、无协作者时，最干净的做法是重建单一初始提交：

```bash
git checkout --orphan clean
git add -A
git commit -m "初始提交：…"
git branch -D main && git branch -m main
git push -f origin main
```

前提：工作区已清理干净（排除项已删、脚本已改）。旧提交会从分支上消失，但可能仍被 GitHub 缓存或本地 reflog 吊着；真要彻底清，删库重建最省事。force push 前确认没有协作者。

## 4. 许可：按内容来源选，不按习惯选

| 内容 | 许可 | 理由 |
|---|---|---|
| 课程笔记、讲义整理、概念页 | **CC BY-NC-SA 4.0** | NC 挡住拿去卖；SA 保证衍生继续开放；BY 满足署名。MIT 允许商用，且会把老师的内容一起「授权」出去 |
| 代码、配置、脚本 | MIT | 与内容分离，单独声明 |

**文件分工**：

- `LICENSE` 只放**协议全文**，前面不要加自定义前言——GitHub 的检测器会因此标成 `NOASSERTION / Other`（不影响法律效力，但页面难看）。
- `NOTICE` 写适用范围与例外：许可只覆盖「自己整理与撰写的部分」；课堂讲义、教师板书、习题原文版权归任课教师与教材作者，不在许可内；权利人要求即删除；转载需注明来源与许可、说明是否修改。
- 代码仓库（MIT）的 README 也要加一句：技能里整理的数学内容版权归原作者，仅供学习。

## 5. 对外 README 的写法（用户偏好）

只写：**是什么 → 目录 → 怎么用 → 依赖 → 许可**。

- **不写维护流水线**：怎么脱敏、怎么同步上传、排除了哪些个人内容，一律不进公开 README——对读者无用，且把内部流程和个人内容清单暴露出去。用户明确要求过这一点。
- 生成来源写一句即可（内容主要由 X 生成，少量来自 Y/Z，经人工核对修改；错误欢迎 issue）。
- 配套的编辑器配置要写**动机**：同一份 Markdown 在不同编辑器里 LaTeX 渲染差别很大（行内公式定界符、反斜杠转义、MathJax 宏），给出「照这套配置能得到一致显示，不想配置可直接照抄」——否则读者不知道这个目录为什么存在。
