# Git 提交卫生、空文件/空链判定、断链清理与验证

> 摘自 `wiki-writing-conventions` SKILL.md（2026-10-03 拆分），内容未改。

### 0 字节文件 ≠ 残留:先看时间戳与来源(2026-09-11 第三次险些误判)

用户说"图谱里有两个没染色的空文件(诺特定理、拉格朗日力学),应该可以删除吧"时,
**不要直接删**。核查证据表明它们是**用户自己几分钟前在 Obsidian 里新建的**:

| 证据 | 判据 |
|---|---|
| **创建时间** | 18:52 / 18:53,而当时是 18:55 —— 就在 3 分钟前 |
| Obsidian **进程在运行** | 用户正在用 |
| `.obsidian/workspace.json` **引用了这两个文件名** | 说明在 Obsidian 里**被打开过** |
| 位置在 vault **根目录**(不是任何概念目录) | 像是随手新建待填 |
| 内容符合**正在学的课程** | 用户正在学理论力学,"诺特定理/拉格朗日力学"正是其内容 |

**结论:不删,先问用户是要我写还是他点错了。**

**一般规则 —— 判"残留"必须看三样,不能只看大小**:
1. **时间戳**:0 字节 + **刚刚创建** = 用户新建的空笔记;**0 字节 + 很久没动** = 才可能是残留。
2. **`workspace.json` 是否引用**:被引用过说明用户在 GUI 里操作过它。
3. **是否贴合用户当前学习进度**:符合在学课程名的空页,几乎一定是"待填的概念页"。

**注意区别**:上一轮我处理 `wikilinks.md`(0 字节)时删得对 —— 那是 Obsidian **反复自动生成**的产物
(删掉后又出现,已加进 `.gitignore`)。同样是 0 字节,**来源不同、处置相反**。
判据:`wikilinks.md` 是工具生成物且反复重现;`诺特定理.md` 是用户主动创建且只出现一次。

**本次最终查明**(见下节):`诺特定理.md`/`拉格朗日力学.md` **既不是用户主动新建、也不是残留**,
而是**空 wikilink 被点击后由 Obsidian 自动创建**的 —— 处置办法在删文件之外,还得掐掉源头那条链接。

### 空 wikilink 会被 Obsidian 建成空文件 —— 根因与永久修法(2026-09-11 查明)

**现象**:vault 根目录凭空多出 0 字节的 `诺特定理.md`、`拉格朗日力学.md`,用户自己也困惑它们哪来的。

**根因(已查实)**:`物理\理论力学\伽利略群.md` 的「相关概念」列表里有
`- [[诺特定理]] — 对称性与守恒量` 和 `- [[拉格朗日力学]] — 拉格朗日形式`,
但目标页不存在。**在 Obsidian 图谱/链接里点击这种指向不存在页面的空链接,Obsidian 会主动新建同名空笔记**
(它的默认交互:点断链 = 创建该笔记)。
**不是**「未链接提及」设置所致 —— 查过 `.obsidian\core-plugins.json`,里面没有相关项。

**处置:不是删文件了事,而要掐掉链接源头**,否则点一次就复现一次:
1. 把空 wikilink 改成**纯文字**,保留「后续会学到」的衔接信息但不建链,与 vault 既有写法一致
   (如 `牛顿决定性原理…md` 的「相关概念」只列真实存在的页):
   `- [[诺特定理]] — 对称性与守恒量` → `- 诺特定理(对称性与守恒量)——后续内容,未创建页面`
2. 删掉已生成的空文件。
3. **全库复查所有 wikilink 目标是否都存在**(脚本见下),确认再无空链。

**排查脚本要点**：建「现存页 basename 集合」，遍历所有 `.md` 抽 `\[\[([^\]]+)\]\]`，
**先剥别名 `|` 与锚点 `#`**，再取 basename 比对；**排除附件扩展名**（`.svg/.png/.jpg/.gif/.pdf` 不算断链）。

**数学环境里的 `[[…]]` 同样是 wikilink**：Obsidian 在 markdown 层解析链接，`$…$`/`$$…$$` 内的双方括号照样被当成链接、也会被断链检查报出来——形式幂级数 `$K[[X]]$` 这类记号要写成 `K[\![X]\!]`（`\!` 是负空格，渲染出的双括号效果不变）。命中这种「内容明显是数学记号」的断链时，**改记号、不要新建页面**。
本次全库 370 个 wikilink 扫完只剩 1 处 —— `log.md` 里的 `[[Fourier讲义2026]]`,属**变更日志的历史记述**
(那行本身写着「删除对已失效实体页的引用」),**不算断链、不要改**。这条已写进 `math-physics-wiki` 的断链检查说明。

**与」0 字节 ≠ 残留」的关系**:上面 §0 教的是「用户说是残留时先别删」;本节是**根因**。
两者结合:遇到凭空出现的空文件,先按 §0 查时间戳/workspace.json 判是不是用户建的,
**再查是不是空 wikilink 被点出来的** —— 若是后者,光删文件是治标。

### 删除 vault 文件前的事实核查纪律(2026-09-11 两次误判)

用户说"某个文件与我的笔记无关,删了吧"时,**不要凭文件名/印象直接给方案**。本次两处翻车:

- 用户说"莫名其妙的 README 和 wiki 毫无关系" → 我理解成根目录 `README.md`(那是 vault 门面,应更新而非删除),花整轮读完并给出"更新版"方案;用户随即澄清指的是 **`node_modules/@napi-rs/canvas/README.md`**。**vault 里常有多个同名文件**(根 `README.md`、各包 `README.md`、`_索引.md`),先 `search_files target=files pattern='README.md'` 定位路径再讨论去留。
- 用户说"以及和它 link 的一些文件" → 我差点把该包内的 `*.d.ts`/`index.js` 当成可独立删除的"关联文件"。**先判"它是不是某个包的内部组成"**:包内 `index.js`/`geometry.js` 是被 `require` 的,**删除单位是依赖包整体,不是包内文件**——顺着字面拆包会直接搞坏它。

**一般规则**:删除任何文件前先建立三件事——**这是什么、谁在用、删了会怎样**;再给方案。用户对"这东西没用"的判断通常正确,但**处置粒度**(删文件 / 删整包 / 删依赖声明 / 只删引用)必须由 agent 给对。用户明确说"直接删"时可以跳过逐项确认,但仍要动手前后各核一次(前:确认无引用;后:`git status` 干净)。

### 删除被跟踪文件后:必须清理"指向它的指令"

删 `共享/SCHEMA.md` 时,skill 库里还剩 **5 处**"写页面前先读 `共享/SCHEMA.md`"的指令——**文件删了但指令还在,下次会话会照着找不到的文件找**。收尾动作:`search_files pattern='<已删文件名>'` 扫 skill 库,逐条改成"该文件已于 X 日删除,内容见 Y"。本次同时修了 3 个技能(含 `math-physics-wiki` 的环境事实与归档流程、`math-notes-transcription` 的目录树、本技能的格式方法来源)共 6 处引用。**删除类任务的工作量一半在删,一半在清理引用。**

### 空目录与保留判断

`git` **不跟踪空目录**,所以空目录既不出现在 `git ls-files` 也不进 GitHub。清理时按**是否还要用**区分:
- 模板残留(如 llm-wiki 的 `queries/`、`docs/`、`example/`)= 删;
- **将来要填内容的课程目录**(如 `代数I\`、`代数II\`、`分析I\`)= **留**——删了将来补笔记得重建目录+索引,而留着零成本(空目录不占仓库空间、不上 GitHub)。

### git 提交操作(实战教训,2026-08)

- **git add -A 前先删除临时文件**:解压的 vault 目录(_inspect_vault)、临时脚本(_find_dups.js 等)会被一起提交,导致 commit 卡死超时
- 提交后检查 `git status --short` 只含目标文件;若误加:`git reset` → 删 `.git/index.lock`(若超时残留)→ 删临时目录 → 重新 add/commit
- 临时目录用 `_` 前缀命名,删起来一目了然
- 大规模移动/查重后,临时脚本和报告文件必须清理(_find_dups.js、_delete_list.txt 等)
- **风格性改动被用户推翻 → 从 git 恢复旧版而非重写**:`git log --oneline --follow -- <仓库内路径>` 找改动前 commit,`git show <commit>:<路径>` 取旧文件内容,整块还原后新提交。2026-09-02 交换图方形↔三角两次反转实战:恢复 `443d90d` 的 CD 方形画法(笔记 3 图+概念页 1 图)比重写快且忠实;仓库内路径用正斜杠,中文路径在 git 里无碍。
- **多行中文 commit message**：**Linux 主力机上直接内联多行 `-m` 就行**（本会话全程如此）：
  `git -c core.safecrlf=false -c i18n.commitEncoding=UTF-8 commit -q -m "第一行
  正文…"`（`core.safecrlf=false` 只是抑制 LF/CRLF 警告）。历史遗留：在 PowerShell 5.1 上
  多行长中文内联会失败，那时才需要先 `write_file` 写 `.txt` 再 `commit -F`——**别把 Windows 老规矩搬到 Linux**。
- **远端出现本地没有的提交（他可能用 GitHub 网页端直接改了 vault）**：`git push` 被拒后
  1) `git fetch origin` + `git log --oneline HEAD..origin/main` 看是哪个提交；
  2) **`git show <sha> --stat` 看它真正改了什么**（对它自己的父提交）——直接 `git diff HEAD..origin/main`
  会显示「你刚写的内容被删除」，那是**错觉**：那个提交基于更旧的快照，diff 里少的是它没包含的你的提交；
  3) 确认无害后 `git pull --rebase origin main` 再 `git push`，**绝不用 `--force`**；
  4) 向他说明一句「远端那个提交是谁、改了什么、我没覆盖它」。



合并/重构笔记时若删除若干概念页,重写其余页面后必须:

1. **确认已删除页文件名**:用 `search_files target=files` 列出概念目录,与任务提及的删除列表比对
2. **只改任务指定的页面**,不顺手改动其他页
3. **保留的 wikilink 只指向现存有效页面**:删除页的 `[[...]]` 链接必须移除
4. **部分覆盖笔记的改写**:合并笔记只覆盖前 N 章时,页面严格对应已覆盖章节;**后续章节内容(如 Cesàro/Fejér/Parseval/L²/Carleson)以"后续章节内容,当前不在范围内"框架带过**(纯文字,不加 `[[wikilink]]`)——既可保留衔接信息又不制造断链、不冒充现行材料

### 歧义链接（同名页）复查脚本的正确写法（2026-10-04 补）

消歧不是一次性的：上一轮改了 167 处 + 代数 II 入库那轮又改了 33 个文件，仍漏掉 `代数II/概念/正交群.md` 里的
裸链 `[[群]]`（用户自己发现的）。全库复查脚本要满足四点，否则会**大量误报**：

1. **剥掉行内代码**（`re.sub(r'`[^`]*`', ...)`）：`log.md` 里 `[[群]]` 常出现在**反引号引用中描述问题本身**，
   不剥掉会报成真链接。
2. **区分路径式与裸名链接**：带 `/` 的按「路径后缀」解析（`rp == t or rp.endswith("/"+t)`），
   只有**裸名**（`[[群]]`）命中 ≥2 文件才算歧义；路径式几乎不会歧义（本库实测 0 处）。
3. **数学记号要单独归类**：`$K[[X]]$`（形式幂级数）会被 Obsidian 当 wikilink；本库约定写成
   `$K[\![X]\!]$`（`\!` 负空格）。**不要**为它建页 —— 改记号。代数 II 的 `K-代数.md`、
   `09-K-代数与极小多项式.md` 各残留 2 处，已按此改。
4. **只看真链接的形态**：附件扩展名（`.svg/.png/.pdf/…`）跳过；`log.md` 的历史记述（已删实体页）
   不算断链。

改完的验收：跑一遍脚本应输出 **真歧义 0 / 真断链 0 / 数学记号 0**（本库 2026-10-04 达到此状态，765 篇、
约 6000 个 wikilink）。改动按 `git` 一节提交，只加目标文件。

**任何编辑都要重跑，哪怕只新增了一条链接**：给概念页补一条「相关概念」是常规动作，但裸链
`[[导群]]` 在代数 I/III 各有同名页就会被脚本判为二义（Obsidian 也会歧义）——本次正是脚本抳出来的。
写下链接→跑脚本→全 0 才提交，不要等着“下次全面复查”。

### 行内公式的边界：`$...$` 两端不能贴空白（2026-10-04 全库查出 16 处）

笔记同时面向 Obsidian 与 pandoc 预览，两种工具的行内公式规则一致但不宽松：
**开 `$` 后不能紧跟空白，闭 `$` 前不能有空白，且闭 `$` 后不能紧跟 ASCII 数字**。
违反时那一对根本不被当成公式，`$` 会原样显示（pandoc 还会把它转义成 `\$`，并可能连带让 xelatex 报
`Missing $ inserted`）。典型写法 `$A = $`、`$\sigma = $` 就错在闭 `$` 前那个空格 ⇐ 应写 `$A =$`。
以控制空格 `\ ` 结尾的公式（`\ , \ $`）不能直接删空格（会变成 `\$`），把 `\ ` 改成 `\,`。

```bash

```

### 第二类二义：概念名与同名“讲义笔记”H1 撞车（nvim 侧才看得出）2026-10-04

用户报「代数的索引里，映射/序关系/多项式环/族/根与重数/有理分式 都指向至少两个文件」——**Obsidian 里完全看不出问题**，
因为两边解析规则不同：

| | 匹配字段 | 后果 |
|---|---|---|
| Obsidian 桌面版 | 文件名 / 路径后缀 / alias | 正常唯一 |
| obsidian.nvim（本机 epwalsh 原版）| `Note.reference_ids` = **{id, 标题（取 H1）, 文件名, stem, aliases}**，先 exact 再 fuzzy | 与概念页同名的讲义笔记（如 `05-映射.md` 的 H1 就是「映射」）也算候选 ⇒ 弹候选列表或**选错文件**（实测 `resolve_note("映射")` 返回的是 `笔记/正课/05-映射.md` ✗）|

**规矩**：链接指向**概念页**时，若存在 H1 与概念名相同的讲义笔记，必须写带路径形式
`[[代数I/概念/映射]]`（而不是 `[[映射]]`）。带路径后 nvim 按路径直达（实测 `resolve_note("代数I/概念/映射")` → 概念页 ✓，`gf` 不再弹候选），
Obsidian 显示不变（仍按 stem 显示）。既有的 `[[代数III/概念/群作用]]` 写法本来就正常，照用。

**检测脚本（本技能自带，直接跑）**：`python3 <技能目录>/scripts/check_wikilinks.py /mnt/e/notes` ——
一次扫四类：裸链二义 / 路径链接二义 / 断链 / 数学记号误判；全 0 时 exit 0，非 0 会列出候选文件。
匹配规则与本机 obsidian.nvim 对齐（见上表），所以「Obsidian 里看不出、nvim 里弹候选」这类才扫得出来。
本次全库查出 6 个词共 53 处（都在代数I，已全部改成 `[[代数I/概念/…]]`，保留别名与锚点）；
改完复查 766 篇：四类均 0 处。
无需 GUI 的探针验证法：真 UI 里 `client:resolve_note(<链接文字>)` / `client:find_notes(...)` 看它选了哪些文件。
