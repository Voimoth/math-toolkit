# 中文自然度检查（去 AI 味 / 去英译腔）

**来源**：2026-10-07 从 `pika_math_learning_toolkit-2.1.5` 的 `obsidian-vault-notes/references/natural-chinese-lint.json`
（外部 AGPL 项目）改造而来。原规则集是按「长文中文写作」调的；这里按本 vault 的场景（数学概念页 / 课程笔记 /
答疑沉淀）重写并加了本 vault 特有的两类（**修改过程泄漏**、**AI 总结腔**）。

**运行**：

```
python3 <技能目录>/scripts/lint_natural_chinese.py /mnt/e/notes/数学/代数/代数III
python3 <技能目录>/scripts/lint_natural_chinese.py --all 某文件.md      # 连低置信度一起报
python3 <技能目录>/scripts/lint_natural_chinese.py --json 某目录        # 机器可读
```

退出码 0 = 无命中，1 = 有命中，2 = 用法/读取错误。自动跳过：fenced code block、行内代码、`$…$` 与 `$$…$$` 数学区、
callout 标记行（`> [!note]`）。白名单里的词（`wikilink`/`frontmatter`/`LaTeX`/`callout` 等）不判。

## 规则类别（10 类）

| 类别 | 典型命中 | 处理 |
|---|---|---|
| 英译腔 | 「使…成为可能」「把 X 接入 Y 上」「进行一个…的操作」 | 换成自然中文搭配 |
| 空名词 | 「候选内容」「局部工作」「提供了信号」「在…层面上」 | 补出具体对象：是定义、反例还是思路 |
| 搭配不稳 | 「问题被查找」「筛查更便宜」 | 补施事者；成本隐喻写清省了什么 |
| 模板句 | 「本质上是」「核心在于」「从三个维度来看」 | 只留真正承载关系的；纯包装删掉 |
| **AI 总结腔** | 「综上所述」「值得注意的是」「本讲的目的在于」「我们可以发现」 | **本 vault 最痛的一类**：概念页不写收尾总结，把结论并进它该在的那一步 |
| 意义拔高 | 「标志着重要时刻」「体现了更深远的意义」 | 保留事实，删评价 |
| 写作预告 | 「接下来我们将讨论」「让我们深入探讨」 | 直接开始 |
| **修改过程泄漏** | 「本节新增了…」「已修正此处」 | 本 vault 明令禁止：描述对象现在是什么，而非这次改了什么 |
| 模糊归因 | 「专家认为」「一般认为」 | 给出明确来源；无来源不要写成事实 |
| 宣传腔 | 「赋能」「抓手」「未来可期」 | 改写为可观察的事实 |

低置信度规则（`--all` 才输出）：「本质上是」「核心在于」「从来不是…而是」「显而易见」「在…层面上」等
——它们在数学文里有时是对的（例如「核心在于」确实收束了已论证的主次关系），只提示不判罪。

## 适用范围（别过度应用）

- **适用**：概念页、答疑沉淀、agent 自己写的正文。
- **不适用**：`笔记/` 下的讲义誊录 —— 那是讲师原话，命中可能是原文如此（实测全库第一轮的两处命中里，
  `分析II/笔记/12-常微分方程.md` 的「本节的目的是」就是讲义导语）。**不要按 lint 去改誊录文本**。
- 全库 767 个 md 实测：首轮仅 2 处命中 → 假阳性率很低，可以当常规护栏跑。

## 关键原则（照抄原设计的正确部分）

1. **lint 只报告，绝不改写**。要改也必须走一次正常的编辑流程（见 `references/large-edit-gate.md`）。
2. **命中 ≠ 写错**。警告是提示；是删是留由写作者判断。低置信规则尤其如此。
3. **不要在数学与代码里扫散文**（脚本已自动跳过）。
4. **别让这条 lint 变成规则清单的无底洞**：新规则要么进上面的类别，要么说明为什么需要一个新类别
 （原项目的教训原话：*do not treat each bad result as a new special case*）。
5. 这是**写作后**的检查，不是写作时的模板。写的时候想的是「这句话换个题目还成立吗」（见 SKILL.md §2），
 不是「这句话会不会被 lint 抓」。
