# Obsidian 图谱配色与 UI 配置（/mnt/e/notes 实战 2026-09-11）

用户要求：笔记一个颜色、各学科概念分别不同颜色，让 Graph View 更清晰。
本文件记录 **graph.json 的字段语义、配色查询的写法与陷阱、以及"改完怎么验"**。

## 一、文件位置与跟踪状态

- 图谱配置：`/mnt/e/notes/.obsidian/graph.json`（JSON，无 BOM UTF-8）
- **`graph.json` 不被 git 跟踪**（`.gitignore` 的 `.obsidian/` 规则命中；仓库里只有 `.obsidian/app.json` 一个被跟踪）。
  所以改它**不会**进 GitHub，也不需要 commit —— 别浪费一轮去提交，也别以为没提交就是没保存。
- 判定方法：`git ls-files '.obsidian'`。

## 二、colorGroups 的语义（关键）

```json
"colorGroups": [
  { "query": "path:笔记", "color": { "a": 1, "rgb": 15277667 } }
]
```

- **`rgb` 是十进制整数**，不是十六进制字符串。换算 `(R<<16)|(G<<8)|B`：
  `#00BCD4`→`48340`，`#FFAA00`→`16755200`，`#E05252`→`14701138`，`#2196F3`→`2201331`，`#43A047`→`4431943`，`#3F51B5`→`4149685`。
  **务必自己算一遍再写** —— 本次两次踩坑：第一版把「蓝色」写成 `37706`（=`#00934A` 绿）与理论力学绿撞车；
  又把笔记配成洋红 `#E91E63`（`15277667`），用户反馈与代数III 的红区分度低而返工。
  换算核对：`[Convert]::ToInt32('<hex>',16)` 与 `(r -shl 16) -bor (g -shl 8) -bor b` 两边对得上才算数。
- `a` 是透明度，固定 `1`。
- **组按数组顺序优先取第一个匹配**，这是最容易错的点（见下节）。
- 完整字段集（Obsidian 1.13.7 写入的固定集合，照抄勿增删）：
  `collapse-filter, search, showTags, showAttachments, hideUnresolved, showOrphans,
  collapse-color-groups, colorGroups, collapse-display, showArrow, textFadeMultiplier,
  nodeSizeMultiplier, lineSizeMultiplier, collapse-forces, centerStrength, repelStrength,
  linkStrength, linkDistance, scale, close`

## 三、查询写法与两个陷阱

用 Obsidian 搜索语法的子串匹配（忽略大小写）。

**陷阱 1：`path:` 里的 `/` 易出问题 → 规避斜杠，只用单个目录名特征词。**
不要写 `path:代数III/概念`；改 `path:代数III`，靠**组顺序**处理"子目录也被父词命中"。

**陷阱 2：组顺序决定归属，`path:笔记` 必须排最前。**
`代数III`、`Fourier` 会同时命中其下的 `笔记/` 目录；学科组若在前，用户的课件笔记会被染成学科色，
违背"笔记单一颜色"的需求。

**实测可用的顺序**（本 vault，**2026-09-11 用户确认的学科级定稿**）：

| 顺序 | query | 颜色 | 色相 | 命中 |
|---|---|---|---|---|
| 1 | `path:笔记` | `#00BCD4` 青绿 | 187° | 4 个笔记/讲义页 |
| 2 | `path:_索引` | `#FFAA00` 橙 | 40° | 7 个索引 |
| 3 | `path:分析` | `#2196F3` 蓝 | 207° | 16 个分析概念页 |
| 4 | `path:代数` | `#E05252` 红 | 0° | 19 个代数概念页 |
| 5 | `path:物理` | `#43A047` 绿 | 123° | 4 个物理概念页 |
| 6 | `path:概率` | `#3F51B5` 靛蓝 | 231° | 0（预留） |

**注意粒度：用学科词，不要用课程词。** 曾按课程级（`path:代数III`/`path:Fourier`）配色，
被用户驳回：「什么代数III之类的分类太细了，到时候找不出这么多颜色用」。
**颜色按学科分配** —— 学科少而稳定，课程会持续新增，按课程分色很快就会色不够用。
学科级还能享受一个便利：单字学科词（`代数`/`分析`）经实测只出现在各自学科树下（0 误伤），
所以不必写带斜杠的路径。**新增学科前先做这个误伤检查**：遍历全库路径，确认该词不出现在别的学科树里。

**层级效果是设计的一部分**：`分析/` 树下 22 个文件只有 16 个染蓝 —— 差额是它的 `笔记\`（第 1 组青绿接走）
和 `_索引`（第 2 组橙接走）。用户要的正是「笔记一色 · 索引用一色 · 概念按学科分色」这三层。

**定色必须查色相间距**：把每个候选色转 Hue（`max=R/G/B` 分情况算），
**最小间距要 ≥ 40°，且不同语义的组不要同色系**。反面案例：`#E91E63`（338°）配 `#E05252`（0°）
仅差 22°，用户直接要求返工；当前版最小间距 40°（橙 40° vs 红 0°）。
纯机检看不出「像不像」，Hue 差是最省事的量化代理。

`_索引` 必须放在学科组**之前**，否则 `物理/理论力学/_索引.md` 会被绿色抢走（应为橙）。
未着色者（合理保持默认灰）：`log.md`、`README.md`、`wikilinks.md`、`共享/templates/*`、及散落在上述目录之外的页。

**新学科预留颜色**：用户会要求给"还没开始的课程"（如概率）预留。照样加一条 `path:<学科名>`，
命中 0 个也无害，将来该目录下建页即自动上色。挑色时避开已用色相。

## 四、改完必须验（只有配置层面可验）

**能本地验的（务必全做，别只肉眼看 JSON）**：
1. **JSON 合法性 + 字段类型**：`ConvertFrom-Json`；逐组查 `query` 是非空字符串、
   `color.rgb` 是 int 且在 `0..16777215`、`color.a -eq 1`。
2. **颜色去重**：每组 rgb 解回 hex 放哈希表，**唯一色数必须等于组数**（本次靠这步抓出绿撞绿）。
3. **编码**：首 3 字节**不得是 `EF BB BF`**（无 BOM），Obsidian 期望无 BOM。
4. **查询词与磁盘目录名逐字符比对**：把 query 特征词与真实目录名各转**码点序列**比对，
   防大小写/同形字不一致。例 `代数III` 两边都须是 `20195,25968,73,73,73`（三个大写 I）。
5. **归属模拟**：写 Node 脚本复现"按序取第一个匹配（`toLowerCase().includes()`）"，
   打印每组命中数与未着色数，与预期对照。用 Node 独立实现（`fs.readdirSync` 递归 + `path.sep`→`/`）
   而非 PowerShell 的 `-like`，等于一次交叉验证；两次独立实现结果一致才可信。

**验不了的（必须跟用户讲明）**：Graph View 的**渲染结果**没有 CLI/API 可脚本化，
无法回读"节点实际显示成什么颜色"。配置层面验完就**停下让用户目测**，
不要为"跑测试"去造临时脚本 —— 用户明令禁止建 `hermes-verify-*.ps1` 这类临时验证脚本
（原话"写好了搞什么验证脚本，你当我眼瞎不会看吗"），核验一律用内联命令。

## 五、Obsidian 正在运行时改 graph.json 的风险

- 改此文件时 Obsidian 通常开着，写文件工具会报
  `was modified since you last read it on disk (external edit or unrecorded writer)`。
  **必须 `read_file` 回读确认拿到的是自己的版本**。
- Obsidian 会在**退出/切换视图时把内存里的图谱设置写回**，可能覆盖外部改动。
  改完要提示用户**先在 Obsidian 里看一眼确认生效**；若他在图谱里拖过节点/改过缩放，
  退出时可能把配置冲掉，必要时重写一次。
- 兜底：`graph.json` 只是视图偏好，删了 Obsidian 会自动重建，坏了也只是显示默认色，不影响笔记。

## 六、改配置前的信息收集

先摸清三样再设计分组：
1. **现有 `colorGroups`**（可能为空 = 全默认色）。
2. **全 vault 页面分布**：按目录列出所有 `.md`（排除 `.git\.obsidian\node_modules`），才知道有哪些学科可分组。
3. **frontmatter 的 `type` 分布**（`concept/summary/notes/entity/learning-path/comparison`）。
   —— 但实践下来**按 `path:` 分组优于按 `type:`**：本 vault 有 38 个 `type: concept` 混在三个学科里，
   用 `type:` 分不出学科；路径天然带学科/课程信息。

## 七、用户对图谱效果的偏好（2026-09-11）

- **粒度：学科级，不要课程级（最重要）**。曾按课程分色被驳回，原话
  「什么代数III之类的分类太细了，到时候找不出这么多颜色用」。**先确认粒度再动手** ——
  这是返工最贵的一处。
- 要求**笔记单独一个醒目颜色**。经两轮返工才定稿：初版灰色 `#9B9B9B` → 用户「换得醒目一点」；
  改洋红 `#E91E63` → 用户「和代数概念的颜色区分度比较低」→ 定稿**青绿 `#00BCD4`**。
  **教训**：给主体内容配色时，①别用灰/淡色；②**别选与已用色同色系的**（洋红与代数的红同属红系）。
  一轮就想命中，定色前先把候选色的 Hue 排开看间距（≥40°）。
- 要求**给尚未开始的学科预留颜色**（概率论），即使该目录当前只有 `_索引.md`。
- 配色基本认可后即可收尾，不必再迭代微调。

## 八、图谱里出现的「凭空多出的空文件」常是空 wikilink 被点出来的

在 Graph View 里点击**指向不存在页面的灰色孤立节点**，Obsidian 会**主动新建同名空笔记**。
所以图谱里冒出 0 字节文件时，除了按 SKILL.md §3「0 字节 ≠ 残留」判是不是用户自建，
**还要查是不是空 wikilink 被点出来的** —— 光删文件治标，必须把那条 `[[...]]` 改成纯文字。
排查与修法见 SKILL.md §3「空 wikilink 会被 Obsidian 建成空文件」。
